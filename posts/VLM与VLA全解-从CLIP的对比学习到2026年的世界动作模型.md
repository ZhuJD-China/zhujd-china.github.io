这是《深度学习专栏》的第十篇。前九篇里，注意力、分词、量化、Infra、推理引擎、评测、编程智能体、推理模型和 Agent 工程，基本都在回答同一个问题：语言模型怎么变强、怎么变便宜、怎么被验证。这一篇换掉输入和输出：模型开始看图，然后动手。

开头先摆三个数字。

2026 年 7 月 30 日，Google DeepMind 发布 Gemini Robotics 2。官方演示里，搭载 22 自由度 SharpaWave 手的 Apollo 2 人形机器人做精密插装，成功率 89.6%；同一个模型从地上捡东西，成功率 45.7%。相差 43.9 个百分点，用的是同一套权重、同一台机器人。发布会重点讲的是前者。

同一个月，MMMU 公开榜单上，第一梯队挤在 83.0 到 83.8 之间。MMMU 的人类专家基线是 88.6。差 4.8 分，传播口径是「接近人类专家」。但如果换成 BLINK 里的视觉感知题，人类是 95.70%，2023 年的 GPT-4V 是 51.26%；此后模型有提升，视觉感知仍然是失分最集中的一类。

第三个数字来自机器人 benchmark。π0.5 在 LIBERO 上报告 96.85%，几乎刷满；同一批模型换到 LIBERO-PRO 的扰动设置——物体位置、背景、初始状态变一变——π0.5 掉到 38%，另外几个模型直接掉到 0%。

三个数字放在一起，说的不是「模型不行」，而是「理解」这个词在 2026 年被用得太宽了。看懂图里的文字、判断两个物体的空间关系、把一句话翻译成一串关节角，是三种不同的能力，有不同的数据、不同的失败方式、不同的评测。把它们统称为「多模态智能」，就像把记账、炒股和印钞统称为「金融」。

这篇文章讲这三件事怎么接起来，以及接起来之后，为什么榜单上的分数仍然兑换不成产线上的成功率。

**最短路径：** 只想选型读 12；只想理解表示链读 3；只关心评测读 5、9；只关心部署读 10。

## 1. 两个分数，两个世界

先把四组数字并排放在一张表里。它们经常被拿来做同一类论证——「AI 已经接近人类」或者「具身智能已经成熟」——但四组数字测的其实是四件不同的事。

| 评测 | 榜单上的数字 | 对照 | 差距 |
| --- | ---: | ---: | ---: |
| MMMU（2026 年前沿） | 83.8（Gemini 3.1 Pro） | 人类专家 88.6 | 4.8 |
| BLINK（视觉感知） | 51.26（GPT-4V，2023） | 人类 95.70 | 44.4 |
| LIBERO → LIBERO-PRO | 96.85（π0.5） | 扰动后 38 | 58.9 |
| Gemini Robotics 2 | 89.6（精密插装） | 45.7（地面拾取） | 43.9 |

![榜单分数与部署场景之间的四道落差](images/vlm-vla-2026/s01-four-gaps.svg)

第一组差距小，因为 MMMU 考的是「知识 + 推理」，而这恰好是语言模型最擅长的部分。MMMU 有 11.5K 道题，覆盖 30 个学科、183 个子领域，题目里带图表、公式、地图、化学结构。模型要得分，主要靠两件事：把图里的信息读出来，再用学科知识推下去。前者是感知，后者是语言模型的老本行。前沿模型把后者做到了极致，所以总分能逼近人类；剩下的 4.8 分，大多卡在前者。

第二组差距大，因为 BLINK 专门挑感知。它的 3,807 道题分布在 14 个任务里：数数、深度排序、屏幕上的对应关系、被遮挡的物体、相似颜色、空间关系。这些问题对人类是「一眼」的事，对模型却要求像素级的空间精度。GPT-4V 的 51.26 是 2023 年的数字，今天的模型肯定更高；但把视觉感知单独拎出来测，分数立刻从「接近人类」掉到「刚过一半」，这个结构性事实没有变。

第三组差距最大，因为 LIBERO 到 LIBERO-PRO 换的是分布。LIBERO 的 130 个任务，物体、场景、初始位置都在训练分布里；LIBERO-PRO 只改了几个变量——物体的位置、背景、初始状态——成功率就从 96.85% 掉到 38%。这不是模型「变笨了」，是它记住的东西比学会的东西多。

第四组看起来像模型问题，其实是任务结构问题。精密插装的物体在桌上、相机看得清、初始位姿由夹具保证；从地上捡东西，物体可能在椅子底下、被遮挡、距离远、光照差，而且失败一次就得重新规划。同一个模型在两种任务上的差距，测的是「任务把多少不确定性留给了模型」。

四组数字的共同点是：**榜单测的是分布里的一个切片，部署面对的是整个分布。** 切片越干净，分数越好看；分布越脏，分数越难看。这中间没有阴谋，只有口径。

## 2. 术语边界：VLM、VLA、WAM

2026 年的文章里，这三个缩写经常混着用。先把边界划清楚，后面才不会把「模型能描述图像」当成「模型能操作机器人」。

**VLM（Vision-Language Model，视觉语言模型）**：输入图像或视频加文本，输出文本。它可以描述、回答、推理、调用工具，但不直接产生动作。典型代表是 Qwen3.5、Gemini 4、Claude 的视觉输入、GPT 的多模态接口。

**VLA（Vision-Language-Action Model，视觉语言动作模型）**：输入图像、指令和机器人本体状态，输出动作序列。动作可以是关节角、末端位姿增量、夹爪开合，也可以是被离散化的动作 token。典型代表是 RT-2、OpenVLA、π0、GR00T N1、Helix。

**WAM（World-Action Model，世界动作模型）**：输入历史观测和动作，预测未来的观测或状态，动作是预测过程的一部分，或者从预测结果里反解出来。典型代表是 DreamZero、VLA-World、DriveWorld-VLA。它和 VLA 的边界目前是模糊的，很多系统同时具备两种能力。

| 维度 | VLM | VLA | WAM |
| --- | --- | --- | --- |
| 输入 | 图像/视频 + 文本 | 图像 + 指令 + 本体状态 | 历史观测 + 动作 |
| 输出 | 文本 | 动作序列 | 未来观测/状态（可含动作） |
| 闭环频率 | 秒级或一次性 | 3–200 Hz | 训练时用，推理时可蒸馏 |
| 主要数据 | 图文对、视频、网页 | 机器人轨迹 | 视频、轨迹、仿真 |
| 典型系统 | Qwen3.5、Gemini | π0.5、GR00T、Helix | DreamZero、VLA-World |
| 主要评测 | MMMU、BLINK、Video-MME | LIBERO、真机、RoboArena | 视频预测、下游成功率 |

把 VLM 接上机械臂，不自动变成 VLA。中间缺三样东西：动作数据、闭环控制、失败恢复。少任何一样，系统都只是一个「看懂了口令的遥控器」。

反过来，VLA 也不等于「端到端」。2026 年量产的机器人系统，大多是分层结构：上层规划、中层策略、下层控制，中间还夹着规则和安全层。π0 的 50 Hz 输出、Helix 的 200 Hz 小脑、GR00T 的 120 Hz 底层，都是分层，不是一个大模型从头算到尾。

WAM 的诱惑在于「可预测」：如果模型能预测「杯子被推一下会往哪倒」，它就能在动作之前评估后果。但预测未来画面的计算量和误差，目前还撑不起高频闭环。2026 年的 WAM 更多用在训练、数据增广和慢速规划上，真正下放到 50 Hz 控制的案例很少。

## 3. 表示链：一张图怎么变成 token

VLM 和 VLA 的第一道工序相同：把图像切成 token。

以 Qwen2.5-VL 的做法为例。图像先被切成 14×14 像素的 patch，每个 patch 过视觉编码器得到一个特征；相邻 2×2 个 patch 的特征再合并，变成一个 token。于是每个视觉 token 覆盖 28×28 像素。一张 H×W 的图，token 数约为：

```
N = ceil(H / 28) × ceil(W / 28)
```

代入常见分辨率：

| 输入 | 网格 | 视觉 token 数 | 相对 720p |
| --- | --- | ---: | ---: |
| 1280×720 | 46×26 | 1,196 | 1.0× |
| 1920×1080 | 69×39 | 2,691 | 2.25× |
| 3840×2160 | 138×78 | 10,764 | 9.0× |
| 720p 视频，1 fps，60 秒 | 60 帧 | 71,760 | 60× |
| 720p 视频，2 fps，60 秒 | 120 帧 | 143,520 | 120× |

![视觉 token 预算：分辨率与帧率如何把上下文吃满](images/vlm-vla-2026/s02-token-budget.svg)

这张表解释了很多工程现象。

第一，4K 不是「更清楚一点」，是 9 倍的 token。模型在 720p 上能跑，不代表在 4K 上还能跑；上下文长度、显存、延迟都会跟着涨。很多团队的「高分辨率模式」最后都退回 1080p 加局部裁剪，因为全图 4K 的收益被 token 成本吃掉了。

第二，视频的 token 数是乘法。60 秒 720p、1 fps 就是 7 万多 token；2 fps 翻倍。Gemini 1.5 的 100 万 token 上下文听起来很大，按这个算法也只够十几分钟的高分辨率视频。所以长视频系统普遍做两件事：降采样和分段。先低频看全局，再对关键片段提高帧率。

第三，注意力的计算量随 token 数平方增长。1,196 个 token 和 10,764 个 token，两两注意力的对数差 81 倍。这就是为什么「支持任意分辨率」和「任意分辨率都便宜」是两回事。

合并本身也是一种取舍。2×2 合并把 token 数压到四分之一，代价是每个 token 丢掉三个 patch 的独立信息。做 OCR 时这个损失可以接受，因为文字有冗余；做小目标检测时不行，一个 12 像素的螺丝孔在合并后只剩不到一个 token，模型看见的是「一块地方」，不是「一个孔」。工业场景常见的做法是不合并，或者只对背景区域合并——这也是为什么通用 VLM 的默认分辨率在产线上经常不够用。

显存也能算。一个 7B 模型，32 层、32 个注意力头、head_dim 128，如果用 MHA、FP16，每个 token 的 KV cache 是：

```
2（K 和 V）× 32 层 × 32 头 × 128 维 × 2 字节 = 512 KiB/token
```

1,196 个 token 约 0.6 GB；换成 8 个 KV 头的 GQA，约 0.16 GB。单看不大，但视频一上万 token，KV cache 就进入 GB 级，而且会跟着并发数线性增长。

### 3.1 视觉编码器：从 CLIP 到动态分辨率

第一代 VLM 的视觉编码器基本是 CLIP ViT：固定输入 224×224 或 336×336，切成 16×16 或 14×14 的 patch，输出一组特征。固定分辨率的好处是简单，坏处是细粒度信息在缩放时丢了。一张 4K 的工业图缩到 336×336，缺陷只剩几个像素。

第二代改成动态分辨率：把大图切成若干子图，每块单独编码，再拼回序列。Qwen2.5-VL 还加了绝对时间编码，让模型知道每一帧在视频里的真实时间，而不是只看到「第 1 帧、第 2 帧」。这对「第 3 秒发生了什么」这类问题很关键。

第三代是原生分辨率（native resolution），编码器直接吃原始尺寸，用可变长度的 token 序列。它省掉了切图的艺术，但把 token 预算问题原样交给了下游。

### 3.2 连接器：32 个 query 还是两层 MLP

视觉特征怎么进语言模型，有三条主流路线。

**Q-Former 路线**（BLIP-2）：用 32 个可学习的 query 去「抽取」视觉特征，输出固定 32 个 token。优点是便宜、稳定；缺点是信息瓶颈明显，32 个 token 装不下密集文字或小物体。

**MLP 投影路线**（LLaVA）：把每个 patch 特征直接过两层线性层，token 数不变。优点是保留细节；缺点是序列长、训练贵。LLaVA 用 558K 预训练对 + 158K 指令数据，证明了「一个简单的投影层 + 高质量数据」就能做出可用的 VLM，这在 2023 年是个重要的反直觉结果。

**早期融合路线**（Chameleon）：把图像也离散成 token，和文本拼成一个序列，从头训练。优点是模态真正统一；缺点是图像 token 的离散化会丢信息，训练成本也高。Chameleon 34B 是这条路的代表。

2026 年的主流是第二条路线的变体：动态分辨率 + 轻量连接器 + 大量高质量图文/视频数据。架构上的差别越来越小，数据配比和训练课程的差别越来越大。

## 4. VLM 的五年：从对比学习到原生多模态

### 4.1 2021：CLIP 把「对齐」变成一门可扩展的生意

CLIP 的做法现在看很朴素：拿 4 亿对图文，用两个编码器分别编码，让匹配的图文在向量空间里靠近，不匹配的远离。训练完，零样本分类就是把类名写成句子，看图像向量和哪个文本向量最像。

ViT-L/14 在 ImageNet 上零样本 75.5%。这个数字在 2021 年是震动性的：没有用过一张 ImageNet 的标签，靠 4 亿对网页图文，做到了当时有监督 ResNet 的水平附近。它证明了一件事：**互联网规模的弱监督，可以替代人工标注的强监督**。

CLIP 的局限也很清楚。对比学习学的是「整体像不像」，不是「细节对不对」。它能区分「狗」和「猫」，但数不清图里有几只狗；能匹配「红色杯子」，但说不清杯柄朝左还是朝右。后来的 VLM 都在补这个短板。

SigLIP 把 softmax 对比换成 sigmoid，去掉了全局归一化，训练更省、batch 更灵活。SigLIP 的一个变体 SigLiT，在 4 块 TPUv4 上训练两天，ImageNet 零样本做到 84.5%。这个数字说明，对比学习的 scaling 曲线还没有走平，但收益已经从「架构创新」转向「数据 + 算力」的工程优化。

### 4.2 2022–2023：从「对齐」到「对话」

Flamingo 是这条路的转折点。80B 参数，冻结视觉编码器和语言模型，只训练中间的 gated cross-attention 层，就能处理任意交错的图文序列。它做 few-shot 的方式很「语言模型」：给几个示例，模型接着往下写。Flamingo 没有开源，但它定下了一个范式：**视觉不是外挂，是可插入语言模型上下文的一种 token**。

BLIP-2 把成本打了下来。冻结图像编码器，冻结语言模型，只训练一个 Q-Former，用 32 个 query 把图像压成固定长度的表示。训练分两阶段：先从图文对学对齐，再生成。它的意义是让「接一个视觉模态」从预训练大工程变成一个小模块。

LLaVA 把门槛降得更低。它没有复杂的连接器，就是两层 MLP；数据是 558K 图文对做预训练、158K 指令数据做微调。LLaVA 的成功让社区意识到：VLM 的瓶颈不是架构，是指令数据的质量。2023 年下半年，大量开源 VLM 都是 LLaVA 的变体。

### 4.3 2024–2026：原生多模态与智能体化

Chameleon 走的是另一条路：把图像 token 化，和文本一起从头训练。34B 的模型在图文任务上接近专用模型，证明早期融合可行。Gemini 1.5 则把上下文推到 100 万 token，能直接吃长视频和长文档；它的技术报告里，视频理解是重点场景。

2025 年之后，开源模型的差距快速缩小。Qwen2.5-VL 用动态分辨率和绝对时间编码，7B 在 MMMU 上 58.6、MMMU-Pro 上 41.0；72B 是 70.2 和 51.1。InternVL3-78B 在 MMMU 上 72.2。2026 年 2 月，Qwen3.5 把总参数推到 397B、激活 17B，上下文 262K，Apache 2.0 许可。开源和闭源在「看图答题」上的差距，从 2023 年的代差，缩到了 2026 年的几个点。

但「开放权重」不等于「可部署」。Qwen3.5 的 397B 总参数，即使只激活 17B，权重也要几百 GB；262K 上下文意味着 KV cache 按需增长。真正落到机器人本体的，通常是 3B 到 8B 的蒸馏版本，或者把大模型放在边缘服务器、小模型放在本体。2026 年的架构问题，越来越多是「模型放哪」，而不是「模型多大」。

| 时间 | 系统 | 规模 | 关键做法 | 留下的问题 |
| --- | --- | --- | --- | --- |
| 2021 | CLIP | 400M 图文对 | 对比学习，零样本 75.5% | 细节、计数、空间关系 |
| 2022 | Flamingo | 80B | 冻结主干 + gated cross-attention | 未开源，成本高 |
| 2023 | BLIP-2 | 32 query | Q-Former 压缩视觉 | 信息瓶颈 |
| 2023 | LLaVA | 7B/13B | 两层 MLP + 158K 指令 | 幻觉、分辨率 |
| 2024 | Chameleon | 34B | 早期融合，图像 token 化 | 训练成本、离散化损失 |
| 2024 | Gemini 1.5 | 未公开 | 100 万 token 上下文 | 长上下文注意力成本 |
| 2025 | Qwen2.5-VL | 7B/72B | 动态分辨率、绝对时间 | 高分辨率 token 预算 |
| 2026 | Qwen3.5 | 397B-A17B | 262K 上下文、Apache 2.0 | 部署成本 |

这张表里真正的变化不是参数，是**评测对象的变化**。2021 年测零样本分类，2023 年测看图对话，2025 年测文档、视频、图表、GUI，2026 年测「能不能用工具完成任务」。每换一次评测对象，上一代的第一名就会掉下来一批。

## 5. VLM 的评测：MMMU 的 84 分与 BLINK 的 51 分

### 5.1 MMMU：知识型多模态的分水岭

MMMU 在 2023 年底发布，11.5K 道题，30 个学科，183 个子领域。题目来自大学考试、教材和竞赛，包含图表、示意图、地图、化学结构、乐谱。它要测的不是「识别图中物体」，是「用图中的信息做专业推理」。

GPT-4V 刚出来时是 56 分，人类专家 88.6。2026 年 11 月，前沿模型在 83 到 84 之间：Gemini 3.1 Pro 83.8，GPT-5.5 83.0，Gemini 3.5 Flash 83.0。三年提升了 27 分左右。

但 MMMU 也在饱和。为了拉开差距，2024 年出了 MMMU-Pro：把选项从 4 个增加到 10 个，加入纯视觉版本（只看图，不给文字提示），并把题目重写成更难的形式。同一批模型在 MMMU-Pro 上普遍掉 16.8 到 26.9 分。这个跌幅比总分更有信息量：它说明模型在「有文字线索」时表现好，在「只能看图」时掉得厉害。

### 5.2 BLINK：把感知单独拎出来

BLINK 的设计思路相反：不考知识，只考「看不看得见」。3,807 道题，14 个任务，包括数数、深度排序、被遮挡物体、相似颜色、空间关系、屏幕对应。人类 95.70%，GPT-4V 51.26%，Gemini Pro 45.72%。

BLINK 的题目对人类是「一眼」的事，对模型却很难，因为答案依赖像素级的细节，而视觉 token 是有损压缩。一个 28×28 的 token 覆盖 784 个像素，颜色、边缘、细小文字都在这一步被平均掉了。模型可以把「图里有几只猫」答对，但把「左边第二只猫的尾巴朝哪」答错。

### 5.3 Video-MME：时间维度又加了一层

Video-MME 有 900 段视频、254 小时、2,700 道题，覆盖短视频、中长视频和长视频。它测的是时间理解：动作顺序、事件因果、跨帧指代。视频的难点不只是 token 多，还有「什么时候看哪一帧」。均匀采样会漏掉关键瞬间，关键帧检测又需要先理解内容，鸡生蛋。

| 基准 | 规模 | 测什么 | 不测什么 |
| --- | --- | --- | --- |
| MMMU | 11.5K 题 / 30 学科 | 专业知识 + 图表推理 | 细粒度感知、动作 |
| MMMU-Pro | 10 选项 + 纯视觉 | 抗捷径、纯视觉推理 | 开放世界、长程 |
| BLINK | 3,807 题 / 14 任务 | 视觉感知 | 知识、语言生成 |
| Video-MME | 900 视频 / 254 小时 | 时间理解 | 交互、控制 |

### 5.4 「接近人类」是一个范畴错误

把 MMMU 的 83.8 和人类 88.6 放在一起，说「只差 5 分」，在算术上没错，在工程上没用。原因有三个。

第一，人类基线的方差没有被报告。88.6 是一组专家在受控条件下的平均分，不同学科之间差距很大；模型的分项差距可能和人类完全不同。总分接近，可能是一部分题超过人类、另一部分题远低于人类相互抵消的结果。

第二，测试集的污染无法完全排除。MMMU 的题目来自公开教材和考试，训练语料里很可能有相似题目。2024 年之后的模型在 MMMU 上的提升，有多少来自能力、多少来自记忆，公开信息不足以拆开。

第三，也是最重要的：MMMU 不测「做什么」。一个模型能答对「这个齿轮的传动比是多少」，不代表它能把齿轮装上去。VLM 的评测和 VLA 的评测之间，隔着一整条动作链。

还有一个更技术性的原因：评测 harness 本身有方差。同一份 MMMU，不同的 prompt、选项顺序、答案抽取规则、是否用 LLM 判分，能差出几个点。公开榜单通常固定一套，但论文里的数字往往来自作者自己的 harness。跨论文比较时，模型差 1 到 2 分，可能只是 harness 差 1 到 2 分。

## 6. 动作链：从语义到动作的四条路

VLA 的核心问题不是「看懂」，是「看懂之后输出什么」。语言模型输出 token，机器人要输出连续值：关节角、末端位姿、夹爪开合。这中间有四种主流做法。

### 6.1 离散动作 token

RT-2 的做法最直接：把每个动作维度离散成 256 个 bin，8 个维度就是 8 个 token，和文本 token 拼在一起，用语言模型的下一 token 预测来训练。好处是复用现成的语言模型栈，坏处是精度被 bin 的宽度锁死，而且动作 token 和文本 token 的语义完全不搭。

RT-2 是 55B 参数，在 6,000 次真机试验上评估。它展示了「网页知识迁移到机器人」的可能性：模型没见过某个物体，但知道「把它放到某个容器里」大概是什么动作。代价是慢——自回归生成 8 个 token，加上 55B 的前向，控制频率上不去。

### 6.2 回归

RT-1 和 OpenVLA 用回归头直接预测连续动作，损失是 L1 或 L2。好处是精度不受 bin 限制，推理一步到位；坏处是「多峰」问题：同一个观察下，向左绕和向右绕都能成功，回归会学成两者的平均，结果撞在中间。

OpenVLA 的 7B 模型在 970k 条轨迹上训练，29 个任务上比 RT-2-X（55B）绝对提升 16.5%，参数少 7 倍。第三方在 H100 上测到约 173 ms 的单次推理，差不多 5.8 Hz，做抓取够用，做动态任务不够。

### 6.3 扩散

Diffusion Policy 把动作序列当成一张「动作图」来去噪：从高斯噪声开始，迭代几十步，得到一条动作轨迹。好处是能表达多峰分布，坏处是推理慢——每步都要过一遍网络，几十步就是几十倍的计算。

扩散策略在 2023 年很火，因为它解决了回归的平均化问题，而且训练稳定。但 10 到 20 Hz 的控制频率，加上几十步去噪，很难塞进高节拍产线。

### 6.4 流匹配

π0 用的是流匹配（flow matching）：学习一个从噪声到动作的速度场，推理时用少量欧拉步积分。它保留了扩散的多峰表达能力，但步数少得多。π0 是 3.3B——3B 的 VLM 主干加 300M 的动作专家——能跑到 50 Hz。

流匹配不是「更聪明的扩散」，是「更省步数的扩散」。在同样的模型容量下，它把推理成本从几十步压到几步，代价是训练目标的设计更敏感。

| 动作头 | 代表 | 输出 | 优点 | 代价 |
| --- | --- | --- | --- | --- |
| 离散 token | RT-2 | 256 bin × 8 维 | 复用语言模型栈 | 精度受限、自回归慢 |
| 回归 | RT-1、OpenVLA | 连续动作 | 一步推理、实现简单 | 多峰平均、撞中间 |
| 扩散 | Diffusion Policy | 动作序列 | 多峰、训练稳 | 几十步去噪、慢 |
| 流匹配 | π0 | 速度场积分 | 少步、50 Hz | 训练目标敏感 |

![动作头的四代做法：从离散 bin 到流匹配](images/vlm-vla-2026/s03-action-heads.svg)

### 6.5 动作分块：把「慢」藏起来

所有 VLA 都面对同一个矛盾：模型推理要几十到几百毫秒，控制环要 5 到 20 毫秒。解法是动作分块（action chunking）：一次预测未来 N 步动作，然后开环执行，执行完再预测下一块。

π0.5 一次预测 50 步。如果控制频率是 50 Hz，50 步就是 1 秒的开环。模型在 76 ms 内算完，剩下的 924 ms 可以拿来算下一块，或者处理别的任务。ACT 的 temporal ensembling 做得更细：每次预测一个块，但只执行前几步，下一块预测出来后做加权平均，减少块与块之间的跳变。

分块的代价是反应变慢。开环 1 秒意味着：如果第 200 毫秒物体被碰倒了，模型要到第 1 秒才会重新规划。在结构化环境里这不是问题，在人机协作场景里就是安全问题。所以不少系统把分块长度做成可调的：节拍快、环境稳定时用长块；人靠近、物体易变时用短块。

时间集成的细节值得展开。ACT 的做法是：每次预测一个长度为 K 的块，但只执行前 m 步（m < K），下一块预测出来后，对重叠区域做指数加权平均。权重随预测时间衰减，越新的预测权重越高。这样块与块之间的跳变被抹平，代价是策略对最新观测的响应被平均掉一部分。m/K 的比例是一个显式的权衡：m 小则平滑但迟钝，m 大则灵敏但抖动。这个参数在论文里通常写成一个固定值，在产线上要按节拍和物体动态范围重调。

## 7. VLA 的三年：从 RT-2 到 Gemini Robotics 2

### 7.1 2022–2023：先把「机器人数据」做成规模

RT-1 是 2022 年的工作：35M 参数，130k 条演示，700 多个任务，在见过的任务上 97% 成功率，控制频率 3 Hz。它的意义不是性能，是证明了「大规模多任务机器人数据」这条路能走通。

RT-2 在 2023 年把 VLM 和机器人动作接起来，55B 参数，用网页图文和机器人轨迹联合微调。它的泛化能力来自网页知识：模型知道「易拉罐」是什么、大概能做什么，所以遇到没见过的易拉罐也能做出合理动作。但 55B 的推理成本，注定它只能做研究原型。

同年，Open X-Embodiment 把 22 种机器人、60 个数据集、100 多万条轨迹汇到一起。这个数据集的意义在于「跨本体」：同一个模型要在不同机械臂、不同夹爪、不同相机布局上工作。RT-2-X 在 OXE 上训练，泛化到未见的机器人本体，成为后来所有开放 VLA 的基线。

### 7.2 2024：开源把门槛打下来

OpenVLA 是 2024 年的分水岭：7B、970k 轨迹、开源权重，29 个任务上超过 RT-2-X，参数少 7 倍。它让一个实验室用几张 A100 就能微调自己的 VLA，而不需要从头训练。

π0 在同一年发布，走的是另一条路：3.3B，流匹配动作专家，50 Hz，10,000 小时、7 种机器人、68 个任务的数据。π0 的重点不是「更大」，是「更像一个控制系统」：它能连续执行长程任务，动作平滑，频率够高。

### 7.3 2025：双系统成为主流

GR00T N1 是 NVIDIA 的 2B 模型，明确分成两个系统：System 2 是 VLM，跑 10 Hz，负责理解；System 1 是扩散/流匹配动作头，跑 120 Hz，负责控制。这个拆分解决了一个架构矛盾：理解要慢、要大；控制要快、要小。

Figure 的 Helix 把双系统推到人形机器人：S2 是 7B 的 VLM，7 到 9 Hz；S1 是 80M 的动作模型，200 Hz；35 个自由度；约 500 小时数据。2026 年 1 月的 Helix 02 又加了 S0：1 kHz 的底层控制，1,000 多小时人类数据，官方演示里把一次四分钟的洗碗拆成 61 个动作。

π0.5 在 2025 年把重点转向开放世界：约 400 小时、100 个家庭的数据，能在家里的新场景做整理。它在 LIBERO 上报告 96.85%，同时把「跨家庭泛化」变成一个可讨论的指标。

### 7.4 2026：从「能演示」到「能交付」

2026 年的发布节奏明显加快。

Gemini Robotics 2 在 7 月 30 日发布，22 自由度 SharpaWave 手，官方说新任务用不到 200 个样本、几小时就能适配。它的分项成功率差异很大：精密插装 89.6%，工具整理 78.9%，通用取放 74.2%，货架 76.3%，桌面 68.4%，地面拾取 45.7%。同一套模型，任务结构不同，数字差一倍。

Helix 02 在 1 月 27 日发布，S0 控制环 1 kHz，训练数据里加入 1,000 多小时人类数据。π0.7 在 4 月发布，主打「可引导」：用自然语言指定风格或目标，零样本洗衣服的效果接近 375 小时专家数据训练的专用策略。GO-2 也在 4 月，提出 ACoT-VLA（动作思维链），在自建的 VLA Bench 上 47.4 分，官方称 1,000 台机器人训练、效率提升 10 倍。

| 时间 | 系统 | 规模 | 关键点 | 控制频率 |
| --- | --- | --- | --- | --- |
| 2022 | RT-1 | 35M | 130k 演示、700+ 任务 | 3 Hz |
| 2023 | RT-2 | 55B | 网页知识 + 机器人动作 | 低频 |
| 2023 | OXE / RT-2-X | 1M+ 轨迹 | 22 种本体、60 数据集 | — |
| 2024 | OpenVLA | 7B | 开源、超 RT-2-X | ~5.8 Hz（第三方） |
| 2024 | π0 | 3.3B | 流匹配、50 Hz | 50 Hz |
| 2025 | GR00T N1 | 2B | 双系统 10/120 Hz | 120 Hz |
| 2025 | Helix | 7B + 80M | 35 DoF 人形 | 200 Hz |
| 2025 | π0.5 | 3.3B | 100 家庭、开放世界 | 50 Hz |
| 2026 | Gemini Robotics 2 | 未公开 | 22 DoF 手、少样本适配 | 未公开 |
| 2026 | Helix 02 | 未公开 | S0 1 kHz、1,000h 人类数据 | 1 kHz（底层） |

这张表最容易被误读的地方是「参数越来越大」。实际上，2026 年的主流不是把模型做大，而是把系统拆细：大模型负责低频理解，小模型负责高频控制，超小模型或控制器负责 1 kHz 的安全环。参数量只是其中一层。

这张表还容易掩盖另一个事实：这些数字来自不同的任务套件，不能直接横比。Gemini Robotics 2 的 89.6% 是精密插装，π0.5 的 96.85% 是 LIBERO 仿真任务，OpenVLA 的 16.5% 是 29 个真机任务的相对提升。把它们放进同一张表，只能看趋势，不能排名。真正要选型时，必须回到自己的任务集上重测——这也是第 9 节要讲的证据链。

## 8. 数据链：一百万条轨迹买不到什么

### 8.1 数据的四个来源

机器人数据有四个来源，成本和保真度各不相同。

**网页图文**：LAION-5B 有 58.5 亿对图文，几乎免费，但没有动作。它教会模型「世界长什么样」，不教「怎么动」。

**人类视频**：第一视角的操作视频，量大、便宜，但没有关节角、没有力反馈、没有精确的时间对齐。Helix 02 用了 1,000 多小时人类数据，说明这条路的性价比在上升，但如何从视频里恢复动作仍然是个开放问题。

**仿真**：成本低、可并行、有完美的标签，但有 sim-to-real 差距。域随机化能补一部分，补不了接触力学、柔性物体、传感器噪声。

**真机轨迹**：最贵，也最直接。OXE 有 100 多万条轨迹、22 种本体、60 个数据集；DROID 有 76k 条轨迹、350 小时、564 个场景、86 个任务；π0 用了 10,000 小时、7 种机器人、68 个任务；π0.5 用了约 400 小时、100 个家庭；Helix 约 500 小时。

![机器人数据的金字塔：网页、视频、仿真、真机](images/vlm-vla-2026/s04-data-pyramid.svg)

### 8.2 数据买得到覆盖，买不到理解

一百万条轨迹能买到什么？能买到「在相似场景里重复成功」的统计规律。买不到的东西至少有四类。

**第一，失败的原因。** 一条成功轨迹只记录「做了什么」，不记录「为什么没做别的」。模型学到的是条件分布的高概率区域，不是因果。遇到新情况，它不知道哪个动作是「安全但低效」、哪个是「高效但会撞」。

**第二，力与接触。** 大多数公开数据集只有位置和夹爪开合，没有力矩、没有触觉。插装、拧螺丝、折衣服这些任务，成功与否取决于接触力，纯视觉策略只能靠位置误差硬扛。

**第三，语义的边界。** 「把桌子收拾干净」在数据里可能对应几百条轨迹，但每条轨迹的「干净」标准不同。模型学到的是平均偏好，不是你想要的偏好。这就是为什么 2026 年的系统开始强调「可引导」——用语言把偏好显式化。

**第四，节拍。** 研究数据集不关心生产节拍，一条 30 秒的轨迹可能包含 10 秒的犹豫。工业场景要的是「2 秒内完成」，数据里的时间分布和产线完全不同。

数据成本还有一层容易被忽略：采集一小时可用轨迹，通常需要一小时以上的操作员时间，加上重置场景、检查失败、标注片段，实际投入往往是数据时长的两到三倍（经验值，随任务复杂度变化）。π0 的 10,000 小时背后，是一个团队几年的采集、清洗和返工。这也是为什么 2026 年的开源数据集仍然集中在少数机构手里。

### 8.3 数据质量比数据量更贵

公开数据集的常见问题：相机标定不一致、时间戳不同步、动作有延迟、episode 切分错误、失败样本被丢掉。这些问题在论文里通常一句「我们做了清洗」带过，在实际训练里会吃掉几个点的成功率。

一个具体的例子：遥操作采集时，操作员的动作和机器人的执行之间有几毫秒到几十毫秒的延迟。如果训练时把「当前帧」和「延迟后的动作」配对，模型学到的策略会系统性地超前或滞后。这个误差在慢速任务里看不出来，在 50 Hz 的插装里就是几毫米的偏差。

## 9. 证据链：LIBERO 的 96.9 与 LIBERO-PRO 的 38

### 9.1 LIBERO 是什么

LIBERO 是 2023 年的终身学习 benchmark，130 个任务，分四类：空间关系、物体、目标、长程。它在仿真里跑，任务短、物体少、场景干净。因为便宜、可复现，它成了 VLA 论文的默认考场。

π0.5 在 LIBERO 上报告 96.85%，这个数字经常被引用成「机器人操作已经解决」。但 LIBERO 的任务分布很窄：物体是固定的几类，初始位置在固定范围，语言指令是模板化的。模型只要记住「看到这个场景就往左」，就能拿到高分。

### 9.2 LIBERO-PRO 改了什么

LIBERO-PRO 的思路很简单：不改任务，只改分布。物体位置随机化、背景替换、初始状态扰动。模型还是那些模型，任务还是那些任务，成功率却塌了：π0.5 从 96.85% 掉到 38%，另外几个模型直接掉到 0%。

这个结果不应该被读成「VLA 是假的」。它应该被读成：**LIBERO 的高分主要来自分布内记忆，不是分布外泛化。** 38% 也不是「真实能力」的估计，因为 LIBERO-PRO 的扰动强度、评估协议、成功判定都还在讨论中。它是一把尺子，量出了「换分布之后还剩多少」，不是「绝对水平」。

成功判定本身也是变量。LIBERO 用脚本判定，规则明确；真机评测常靠人工看视频，不同标注者对「算不算成功」的阈值不一样。同一段视频，有人看到「杯子放进了架子」，有人看到「杯子碰到了架子边缘」。在 90% 附近的成功率上，1 到 2 个点的差异很可能来自判定，而不是策略。

### 9.3 更好的证据：分布式真机评测

2025 年的 RoboArena 试图解决「每个实验室各测各的」问题：多个机构用同一套协议，在各自的真机上做成对比较，用 Elo 汇总。它的好处是去中心化、减少单实验室的过拟合；坏处是成本高、任务集有限、仍然依赖人工判定。

MolmoSpaces 提供 23 万个场景，用于大规模仿真评测；DreamZero 在 2026 年 4 月的 RoboArena 上报告 1,750 Elo。这些数字比 LIBERO 更接近真实，但仍然不是产线。

### 9.4 统计：0 次失败不等于 0 风险

机器人评测最常见的错误，是拿 10 次成功当「可靠」。用 Clopper-Pearson 的精确上界，0 失败时 95% 置信区间的上限约为：

| 试验次数 | 0 失败时的 95% 上界 |
| ---: | ---: |
| 10 | 25.9% |
| 50 | 5.8% |
| 100 | 3.0% |
| 300 | 1.0% |

也就是说，10 次全成功，真实失败率可能高达 26%。要在 95% 置信度下说「失败率低于 1%」，至少需要 300 次独立试验。这个计算不复杂，但它在 demo 视频里几乎从不出现。

| 证据等级 | 例子 | 能证明 | 不能证明 |
| --- | --- | --- | --- |
| 厂商视频 | 发布会剪辑 | 任务可行 | 成功率、泛化 |
| 论文榜单 | LIBERO 96.9 | 分布内性能 | 真实场景 |
| 扰动评测 | LIBERO-PRO 38 | 分布偏移下的保留率 | 绝对能力 |
| 第三方复现 | 独立实验室 | 可复现性 | 产线节拍 |
| 影子运行 | 不接执行机构 | 真实分布下的稳定性 | 长期可靠性 |
| 产线数据 | 连续生产 | 节拍、误报、维护 | 新任务泛化 |

## 10. 部署：20 毫秒的控制周期怎么塞进 76 毫秒的模型

### 10.1 控制环的层级

一台典型的协作机器人，控制环至少有三层：

- **安全环**：1 kHz，1 ms 周期，负责急停、力矩限制、碰撞检测。这一层不能用学习模型，必须是确定性的。
- **底层控制**：100–200 Hz，5–10 ms 周期，负责关节伺服、轨迹插值。Helix 的 S1 是 200 Hz，GR00T 的 S1 是 120 Hz。
- **策略层**：7–50 Hz，20–143 ms 周期，负责「下一步做什么」。π0 是 50 Hz，Gemini Robotics 2 未公开，Helix 的 S2 是 7–9 Hz。

π0.5 在 RTX 4090 上的推理延迟，第三方测到 76 ms（无优化）和 97 ms（含预处理）。76 ms 对应 13 Hz，塞不进 20 ms 的控制周期。所以它必须靠动作分块：一次算 50 步，开环执行 1 秒。

![控制层级与延迟预算：1 kHz 安全环到 50 Hz 策略层](images/vlm-vla-2026/s05-latency-ladder.svg)

### 10.2 显存与量化

| 模型 | 参数量 | BF16 权重 | INT8 权重 |
| --- | ---: | ---: | ---: |
| 7B VLA | 7B | 14 GB | 7 GB |
| π0 | 3.3B | 6.6 GB | 3.3 GB |
| SmolVLA | 450M | 0.9 GB | 0.45 GB |

权重只是一部分，KV cache、视觉编码器的激活、动作分块的缓存都要算进去。7B 模型在边缘设备上跑 50 Hz，通常需要 INT8 或 INT4 量化，加上算子融合和并行解码。OpenVLA-OFT 的论文报告，通过并行解码、动作分块和连续动作头，吞吐提升 25 到 50 倍；这类工程优化对实际部署的影响，往往比换一个更大的模型更大。

### 10.3 延迟藏在哪里

动作分块把延迟藏在了「开环执行」里，但也把风险藏了进去。三种常见做法：

**同步分块**：算完一块，执行一块。实现简单，但推理时机器人停着，节拍被拉长。

**异步分块**：执行当前块的同时算下一块。需要预测「下一块开始时机器人会在哪」，块与块之间要做对齐。

**时间集成**：ACT 的做法，每次只执行块的前几步，下一块出来后加权平均。平滑，但会引入额外的滞后。

### 10.4 失败模式

部署阶段的失败，很少是「模型不会」，多是「环境变了」：

- **光照**：产线换灯、窗户反光，视觉分布变了；
- **相机位姿**：碰撞后相机偏了 2 毫米，末端定位就偏了；
- **遮挡**：人站到相机前，模型看到的是手臂而不是物体；
- **物体变化**：新批次的包装颜色变了，抓取点预测失效；
- **人机接近**：人进入工作区，安全系统降速或停机，节拍崩了。

这些失败不会出现在 benchmark 里，因为 benchmark 的环境是固定的。它们也不会出现在 demo 视频里，因为 demo 会重拍。它们只出现在连续运行的第 3 天、第 17 天、第 43 天。

延迟也一样，要看长尾。p50 是 76 ms，不代表第 95 百分位也是 76 ms；视觉编码器的输入尺寸、场景复杂度、并发请求都会把 p95 推高。产线节拍按 p95 设计，不按均值设计。一个常见的工程做法是：把动作块长度按 p95 延迟留余量，而不是按 p50 卡点。

## 11. 2026 年的路线分歧：VLA、WAM 与车端

### 11.1 操作场景：VLA 还是 WAM

2026 年的操作模型有两条路线。

一条是 **VLA 路线**：观测 → 语言/视觉表示 → 动作。π0.5、GR00T、Helix、Gemini Robotics 2 都在这条线上。它的优点是直接、数据效率高、控制频率容易做上去；缺点是「只会做，不会想」——模型不显式预测后果，遇到新情况靠泛化硬扛。

另一条是 **WAM 路线**：观测 + 动作 → 未来观测。DreamZero、VLA-World、DriveWorld-VLA 属于这一类。它的优点是能评估「如果我这么做，会发生什么」，适合长程规划和多步推理；缺点是预测误差会累积，计算量大，高频闭环难。

NVIDIA 在 2026 年 8 月预览了 GR00T N2，明确说它基于 DreamZero 的 WAM 架构，在 MolmoSpaces 上成功率翻倍，但「尚未发布」。这个措辞很重要：WAM 目前是路线图，不是交付物。

WAM 的训练信号也比 VLA 多一层。VLA 只监督动作，WAM 同时监督未来观测，等于给模型加了一个「预测世界」的辅助任务。这个辅助任务在数据稀疏时尤其有用：动作标签少，但视频帧多。DreamZero 官方说 30 分钟、55 条轨迹就能适配新任务，如果这个数字成立，它说明的不是「WAM 样本效率高」，而是「视频预训练已经把世界规律学进去了」。

### 11.2 车端：另一种 VLA

自动驾驶是 VLA 的一个特殊分支：动作空间是二维的（油门/刹车、转向），控制频率 10–50 Hz，评测靠里程、接管率、碰撞率。它和操作场景的差别，比「四个轮子 vs 两条腿」大得多。

2026 年，车端的路线分歧集中在三件事：纯视觉还是激光雷达、端到端还是 VLA、车端模型多大。NVIDIA 的 Alpamayo 1 是 10B 的推理 VLA，1,727 小时、25 个国家、2,500 多个城市的数据，开放权重。它的思路是用「推理」解释决策，再输出轨迹；这和操作 VLA 的「直接出动作」是两种哲学。

这部分我在[《从 HydraNet 到端到端》](post.html?file=从HydraNet到端到端-特斯拉自动驾驶算法五年与学术界复现对照.md)和[《国产智驾大横评》](post.html?file=国产智驾大横评-七家车企的技术路线与量产口径.md)里已经拆过，这里不重复。只强调一个差异：**车端的「安全」是产品责任，操作场景的「安全」是产线节拍。** 前者要求可解释、可审计、可召回；后者要求不撞、不停、不慢。同一个 VLA 架构，落到两个场景，工程重点完全不同。

| 维度 | 操作 VLA | 驾驶 VLA | WAM |
| --- | --- | --- | --- |
| 动作空间 | 关节/末端 6–30 维 | 2 维（转向、加减速） | 观测/状态 |
| 频率 | 3–200 Hz | 10–50 Hz | 低频规划 |
| 数据 | 遥操作轨迹 | 路测、影子模式 | 视频、仿真 |
| 评测 | 成功率、扰动 | 里程、接管、碰撞 | 预测误差、下游 |
| 失败代价 | 停机、返工 | 人身安全 | 规划偏差 |

## 12. 选型表与十二条落地清单

### 12.1 先问四个问题

选型不需要先看模型排行榜，先问四个问题：

1. **任务是否固定、物体是否已知？** 是，先用经典视觉 + 规则，VLM 只做复核；
2. **是否需要多步、长程？** 否，单任务 VLA 微调就够；是，考虑双系统或任务编排；
3. **环境是否开放？** 否，专用策略更稳；是，通用 VLA + 护栏；
4. **控制周期是否小于 20 ms？** 是，模型只能放在慢环，快环用控制器；否，端到端 VLA 才有的谈。

![VLA 选型决策树：从任务结构到部署形态](images/vlm-vla-2026/s06-selection-tree.svg)

### 12.2 场景与方案

| 场景 | 首选 | 备选 | 不建议 |
| --- | --- | --- | --- |
| 固定工位上下料 | 经典视觉 + 规则 | 小 VLA 微调 | 通用大模型 |
| 无序抓取 | 3D 视觉 + 抓取检测 | VLA 微调 | 纯 2D VLM |
| 柔性装配 | 双系统 VLA + 力控 | 扩散策略 | 纯回归策略 |
| 长程整理/仓储 | 双系统 + 任务编排 | WAM 规划 | 单块端到端 |
| 开放世界家务 | 通用 VLA + 遥操作兜底 | 分层策略 | 无人值守 |

### 12.3 十二条清单

1. **成功定义可测量**：不是「看起来成功」，是「插到底、拧到位、放进格口」。
2. **先采 100 条演示，且包含失败**：失败样本决定模型知不知道边界。
3. **固定相机与标定，记录时间戳**：动作延迟是隐形误差。
4. **同一初始条件跑 10 次**：先看方差，再看均值。
5. **至少三档扰动**：位置、光照、背景，各测一轮。
6. **测 p50 和 p95 延迟**：均值会骗人，长尾决定节拍。
7. **动作块长度与节拍匹配**：50 步 @50 Hz 是 1 秒开环，想清楚这 1 秒里能发生什么。
8. **安全停止独立于模型**：急停、力矩限制、碰撞检测不能跑在 VLA 里。
9. **影子运行至少两周**：不接执行机构，和人工结果对比。
10. **报置信区间**：0 失败不等于 0 风险，10 次全成功的上界是 26%。
11. **保留回退策略**：规则、遥操作、人工接管，至少有一条。
12. **记录每次干预**：干预就是下一轮训练数据，闭环比模型更重要。

这十二条里，只有第 7 条涉及模型输出的使用方式，第 10 条涉及评测纪律，其余都是工程。这不是说模型不重要，是说 2026 年的瓶颈已经不在模型结构上。一个 3B 的 VLA 加上正确的数据、延迟预算和安全层，通常比一个 70B 的模型硬塞进 20 ms 的环路更可用。

粗略算一笔账（经验值，仅作量级参考）：采 100 条、每条 2 分钟的演示，是 3.3 小时数据；按 2 到 3 倍的采集与清洗投入，约 7 到 10 个工时。用 7B 模型做 LoRA 微调，单机 8 卡 A100 一天左右能跑完一轮；推理端一张 RTX 4090 可以跑 3B 级模型，7B 需要量化或双卡。真正的大头不是训练，是场景重置、失败复现和长期影子运行的人力。

## 13. 总结

回到开头那三个数字。

MMMU 的 83.8 和人类 88.6 差 4.8 分，这 4.8 分主要卡在视觉感知；BLINK 的 51.26 和人类 95.70 差 44 分，说明「看懂」在细粒度上还差得远；LIBERO 的 96.85 和 LIBERO-PRO 的 38 差 59 分，说明高分里相当一部分是记忆；Gemini Robotics 2 的 89.6 和 45.7 差 44 分，说明任务结构对成功率的影响不亚于模型能力。

四组数字，四条链：

- **表示链**决定模型能看见什么：分辨率、token 预算、编码器、连接器；
- **动作链**决定模型能做什么：动作表示、频率、分块、延迟；
- **数据链**决定模型能泛化到什么：覆盖、失败、力、语义；
- **证据链**决定你敢不敢上线：benchmark、扰动、第三方、影子、产线。

这四条链里，任何一条断了，榜单分数都兑换不成成功率。反过来，四条链接上了，一个 3B 的模型也能在产线上干活。

2026 年的 VLM 和 VLA，最容易被高估的是「理解」，最容易被低估的是「系统」。模型决定你能看见多少种情况，数据决定这些情况在训练里出现过没有，控制决定看见之后来不来得及动，证据决定动完之后敢不敢说它可靠。

Gemini Robotics 2 的 89.6% 和 45.7% 之间，隔着的不是 44 个百分点，是两种任务结构。MMMU 的 84 分和人类的 88.6 之间，隔着的不是 5 分，是「答题」和「做事」的区别。

把这两个区别想清楚，比追下一个榜单更有用。
