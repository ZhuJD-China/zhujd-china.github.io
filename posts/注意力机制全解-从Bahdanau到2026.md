## 1. 引子：为什么需要注意力机制

在 attention 出现之前，处理"一个序列生成另一个序列"（比如机器翻译）的主流做法是 **RNN/LSTM 编码器-解码器（Seq2Seq）**：编码器把整句话压缩成**一个固定长度的向量**，解码器再从这一个向量里"解压"出译文。

问题很直观：一句 50 个词的话和一句 5 个词的话，最终都被压成同样大小的一个向量。句子越长，压缩损失越大——模型在生成后面的词时，早就"忘了"句子开头说了什么。这个"定长瓶颈"是注意力机制诞生的直接原因。

**核心思想只有一句话：与其把整个输入压成一个向量，不如让解码器在生成每一个词的时候，都能"回头看"输入序列的所有位置，并且自己决定该更关注哪些位置。**

## 2. 注意力机制的诞生（2014-2015）

### 2.1 Bahdanau Attention（加性注意力）

2014 年，Bahdanau、Cho 和 Bengio 提出：解码器在生成第 `t` 个输出词时，不再只依赖编码器最后一个隐状态，而是对编码器**每一个位置**的隐状态 `h_1, h_2, ..., h_n` 计算一个"相关性得分"，再加权求和得到一个"上下文向量" `c_t`。

计算过程可以这样理解：

```
score(s_{t-1}, h_i) = v^T · tanh(W_s · s_{t-1} + W_h · h_i)   # 一个小型前馈网络打分
α_{t,i} = softmax_i(score(s_{t-1}, h_i))                       # 归一化成权重
c_t = Σ_i α_{t,i} · h_i                                         # 加权求和
```

因为打分函数是一个可学习的小神经网络（加法+tanh），所以叫"加性注意力"（Additive Attention）。

### 2.2 Luong Attention（乘性注意力）

2015 年 Luong 等人提出了更简单、计算更快的版本，直接用点积衡量相关性：

```
score(s_t, h_i) = s_t · h_i        # 或者加一个可学习矩阵：s_t^T · W · h_i
```

这个"用点积算相似度"的思路，两年后被 Transformer 直接继承并发扬光大——这就是后来"Scaled Dot-Product Attention"里"Dot-Product"的来源。

**关键收获**：从一开始，注意力机制做的事情就是三步——**打分（多相关）→ 归一化（权重加起来等于1）→ 加权求和**。后面所有的变体，本质上都是在这三步上做文章：怎么打分更快、要不要对所有位置都打分、算完的结果怎么少占显存。

## 3. Transformer 与缩放点积注意力（2017）

2017 年论文《Attention Is All You Need》做了一件激进的事：**把 RNN 整个扔掉**，只用注意力机制（加上前馈网络）就能完成序列建模，还能大规模并行训练。这就是我们今天说的 Transformer。

### 3.1 Query / Key / Value 的直觉

把注意力机制想象成一次"图书馆检索"：

- **Query（查询，Q）**：你想问的问题，"我需要什么信息"
- **Key（键，K）**：每本书的索引标签，"我这里有什么信息"
- **Value（值，V）**：书的实际内容

你拿着 Query 去和每一个 Key 比对相似度（点积），相似度高的书就多参考一点，相似度低的书就少参考一点，最后把所有书的内容（Value）按相似度加权，就是你最终得到的答案。

在 Transformer 里，Q、K、V 都是同一个输入向量 `x` 经过三个不同的线性变换得到的：

```
Q = x · W_Q
K = x · W_K
V = x · W_V
```

### 3.2 缩放点积注意力公式

```
Attention(Q, K, V) = softmax( Q · K^T / √d_k ) · V
```

逐步拆解：

1. `Q · K^T`：每个 query 和每个 key 做点积，得到一个 `[序列长度, 序列长度]` 的相关性矩阵（也叫注意力分数矩阵）。
2. `/ √d_k`：**为什么要除以 √d_k？** 当 key 的维度 `d_k` 较大时，点积的方差会随维度线性增长，数值会变得很大，导致 softmax 后梯度趋近于 0（饱和）。除以 `√d_k` 是为了把方差重新拉回到 1 附近，让 softmax 的梯度保持健康。这是一个很小但很关键的工程细节。
3. `softmax(...)`：把每一行归一化成"和为 1 的权重分布"。
4. `· V`：用这些权重对 Value 做加权求和，得到输出。

### 3.3 多头注意力（Multi-Head Attention）

只用一组 Q/K/V 做一次注意力，模型只能学到"一种"相关性模式。多头注意力把 `d_model` 维的向量切成 `h` 份（比如 8 头、32 头、128 头），每一份独立做一次缩放点积注意力，再把结果拼接起来：

```
head_i = Attention(Q·W_Q^i, K·W_K^i, V·W_V^i)
MultiHead(Q,K,V) = Concat(head_1, ..., head_h) · W_O
```

直觉上，不同的头可以专注于不同类型的关系——有的头关注语法结构（比如主谓一致），有的头关注语义相关的实体，有的头关注紧邻的局部依赖。

### 3.4 自注意力、因果掩码

- **自注意力（Self-Attention）**：Q、K、V 都来自同一个序列，用来建模一句话内部词与词的关系。
- **交叉注意力（Cross-Attention）**：Q 来自解码器，K/V 来自编码器（或者来自 KV Cache），用于生成任务里"参考已有信息"。
- **因果掩码（Causal Mask）**：像 GPT 这样的自回归模型，生成第 `t` 个词时不能看到第 `t+1` 个及以后的词，所以要在 `Q·K^T` 矩阵的上三角部分填上 `-∞`，softmax 之后这些位置的权重自然变成 0。

### 3.5 位置编码：模型如何知道"顺序"

注意力机制本身是"位置无关"的——打乱输入顺序，Attention 的计算结果只是被同样打乱，模型分不出"猫追狗"和"狗追猫"的区别。所以需要额外注入位置信息：

- **正弦位置编码（原始 Transformer）**：用不同频率的 sin/cos 函数给每个位置生成一个固定向量，直接加到输入embedding上。
- **RoPE（旋转位置编码，2021）**：不是"加"位置信息，而是把 Q、K 向量按位置角度做"旋转"，让两个 token 的点积天然只依赖于它们的**相对**位置差。这是目前几乎所有主流大模型（LLaMA、Qwen、DeepSeek、GLM 等）的标配。
- **ALiBi（2021）**：不改 Q/K，而是直接在注意力分数上加一个和距离成正比的惩罚项，越远的 token 得分越低，实现简单且外推性好。

这里先做个记号：后面第 7 节讲到的 MLA，其中一个技术难点就是"低秩压缩"和"RoPE 天然要求的相对位置结构"如何相容——这是它被称为"decoupled RoPE"（解耦 RoPE）设计的原因。

## 4. 推理时代的第一个瓶颈：KV Cache 与 MQA / GQA（2019-2023）

到这里为止讲的都是"训练时怎么算"。但大模型真正大规模落地之后，**推理（inference）阶段的瓶颈和训练完全不同**，这也是 2019 年之后注意力机制演进的主线之一。

### 4.1 自回归生成与 KV Cache

生成式模型是一个词一个词往外蹦的（自回归）。如果每生成一个新词都要把前面所有词的 K、V 重新算一遍，那生成第 10000 个词时就要重算 9999 个词的 K/V，代价随长度平方增长，完全不可接受。

解决办法很朴素：**把已经算过的 K、V 缓存起来**，生成新 token 时只需要计算这一个新 token 的 Q、K、V，然后把新的 K/V 追加进缓存，用新的 Q 去和"缓存的全部 K/V + 自己"做注意力。这就是 **KV Cache**。

### 4.2 显存爆炸问题

KV Cache 虽然省了计算，但极其吃显存。每一层、每一个注意力头都要为每一个 token 存一份 K 向量和一份 V 向量。粗略估算：

```
KV Cache 大小 ≈ 2（K和V） × 层数 × 头数 × 每头维度 × 序列长度 × batch size × 每个数字占用的字节数
```

对于一个几十层、上百个头的大模型，几万 token 的上下文，KV Cache 很容易超过参数本身占用的显存。这直接限制了能同时服务多少并发用户、能支持多长的上下文——这也是为什么"降低 KV Cache"成了过去几年注意力机制演进最重要的一条主线，本文后面讲的 MQA、GQA、MLA、DSA 本质上都是在打这一场"KV Cache 攻防战"。

### 4.3 Multi-Query Attention（MQA，Shazeer，2019）

最直接的思路：**多个 Query 头共享同一组 Key/Value 头**。也就是说，不管你有多少个 Query 头，Key 和 Value 都只算一份、存一份。

```
标准 MHA 的 KV Cache ∝ 头数（比如 32 头）
MQA 的 KV Cache      ∝ 1（只有一组 K/V）
```

好处是显存直接降低几十倍；代价是所有 Query 头被迫"共用同一套参考资料"，模型表达能力会打折扣，实践中会带来一定的精度损失。

### 4.4 Grouped-Query Attention（GQA，Ainslie 等，2023）

GQA 是 MHA 和 MQA 的折中：把 Query 头分成若干组，**同一组内的 Query 头共享一组 K/V**，组数是一个可调超参数（比如 32 个 Query 头分成 8 组，每组 4 个 Query 头共享 1 组 K/V）。

```
组数 = 1        → 退化成 MQA
组数 = 头数      → 退化成标准 MHA
组数介于两者之间   → GQA，效果接近 MHA，显存接近 MQA
```

GQA 在效果和效率之间取得了很好的平衡，从 LLaMA 2/3 开始被绝大多数主流大模型采用，直到今天依然是"最经典、最保守"的高效注意力方案（2026 年仍有像 MiniMax M2.5 这样的模型坚持只用朴素 GQA，不叠加其他花活）。

## 5. 硬件感知的精确注意力：FlashAttention 系列（2022-2026）

前面 MQA/GQA 是通过"减少要存的 K/V 数量"省显存，FlashAttention 走的是完全不同的一条路：**不改变注意力的数学结果（精确注意力），而是改变计算它的方式，让它更适配 GPU 的内存层级结构**。

### 5.1 问题所在：注意力是"内存受限"的

标准实现要先算出完整的 `Q·K^T` 矩阵（大小是序列长度的平方），写入 GPU 显存（HBM），再读出来做 softmax，再写回去，再读出来做和 V 的乘法……这一堆读写在长序列时远比矩阵乘法本身的计算量更耗时——注意力其实不是"算得慢"，而是"数据来回搬得慢"。

### 5.2 FlashAttention（2022）：IO 感知、在线 softmax

核心技巧：把 Q、K、V 切成小块（tile），每次只把一小块数据从显存搬到 GPU 芯片上速度快得多的高速缓存（SRAM）里，在芯片上把这一小块的注意力算完，**全程不把完整的 `[n, n]` 注意力矩阵写回显存**。为了在分块计算时依然得到数学上完全正确的 softmax 结果，用了"在线 softmax"技巧，边算边用一个运行中的归一化因子做修正。

结果：数学上和标准注意力**完全等价**（不是近似！），但因为大幅减少了显存读写，实际速度快好几倍，还能支持更长的上下文。

### 5.3 后续版本：跟着硬件一起进化

| 版本 | 时间 | 核心变化 |
|---|---|---|
| FlashAttention | 2022 | 提出 IO 感知的分块 + 在线 softmax，奠基之作 |
| FlashAttention-2 | 2023 | 把内层循环从"按 K/V 切分"改为"按 Q 切分"（Split-Q），减少线程间同步开销，并行效率大幅提升 |
| FlashAttention-3 | 2024 | 针对 Hopper 架构（H100）做异步执行、warp 专精化，并支持 FP8 低精度计算 |
| FlashAttention-4 | 2026.3 | 针对 Blackwell 架构（B200/B300）"非对称硬件扩展"问题（Tensor Core 算力翻倍，但共享内存带宽、指数运算单元没跟上）重新设计流水线，用软件模拟指数函数缓解 softmax 瓶颈，B200 上 BF16 精度可达约 1600 TFLOPs/s |

**一个重要认知**：FlashAttention 系列**不减少 KV Cache 的大小**，它优化的是"算得快不快"；而 MQA/GQA/MLA/DSA 这些优化的是"要存多少、要读多少"。这两条线是正交的、可以叠加使用的——事实上今天几乎所有推理框架（vLLM、SGLang 等）都是"GQA/MLA + FlashAttention 内核"组合拳。

## 6. 稀疏注意力的探索：从 Longformer 到 NSA、DSA（2019-2025）

不管是 MQA/GQA 还是 FlashAttention，本质上都还是在算"每个 token 和之前所有 token 的关系"，计算量依然是序列长度的平方级（O(n²)）。当上下文长度冲到几十万甚至百万 token 时，这个平方项本身就是天花板。稀疏注意力的思路是：**每个 token 其实不需要真的关注所有历史 token，只要关注其中"重要"的一小部分就够了**。

### 6.1 早期静态稀疏方案

2019-2020 年前后出现了一批"人工设计"的稀疏模式：

- **Sparse Transformer**：让每个 token 只关注固定间隔或固定局部窗口内的 token。
- **Longformer / BigBird**：组合"滑动窗口注意力"（只看附近 w 个 token）+"全局 token"（少数几个特殊 token 可以被所有位置关注，也能关注所有位置），复杂度降到接近 O(n)。

这类方案的问题是**稀疏模式是人为设定死的**，不知道对当前这句话来说，到底哪些 token 才是真正重要的——固定的滑窗可能恰好漏掉一个很远但很关键的引用。

### 6.2 Native Sparse Attention（NSA，DeepSeek，2025.2）

NSA 拿到了 ACL 2025 最佳论文奖，思路是让"哪些 token 重要"变成**可学习、可端到端训练**的，而不是人工规定。NSA 把每次注意力计算拆成三个并行分支，结果再门控融合：

1. **压缩分支（Compression）**：把连续的一小段历史 token 压缩成一个"摘要"表示，用于捕捉粗粒度的全局信息。
2. **选择分支（Selection）**：基于压缩分支算出的重要性得分，动态挑选出最重要的若干个 token 块，做精细的注意力计算。
3. **滑窗分支（Sliding Window）**：始终保留对近邻 token 的稠密注意力，保证局部连贯性不丢。

三个分支的输出通过一个可学习的门控加权融合。因为整个流程可微分，NSA 可以**从预训练阶段就直接用稀疏注意力训练**（而不是训练用稠密、推理再稀疏化打折扣），论文里报告在 64k 长度下解码、前向、反向传播全阶段都有实打实的加速，同时基准测试效果不输标准全注意力。同期还有 Kimi 团队提出的 **MoBA（Mixture of Block Attention）**，思路类似，是把历史序列切块、用一个类似 MoE 路由的机制挑选相关的块。

### 6.3 DeepSeek Sparse Attention（DSA，DeepSeek V3.2，2025 年底）

DSA 是 NSA 思路的延续和"精细化"版本，2025 年底随 DeepSeek-V3.2 系列发布，后来被 GLM-5 系列等模型跟进采用。核心是两个组件：

1. **Lightning Indexer（轻量索引器）**：用一个非常轻量的打分函数，快速估算当前 query 和历史每一个 token 的相关性得分。
2. **Top-k 选择器**：只保留得分最高的 `k` 个（默认 k=2048）历史 token，真正的注意力计算只在这被选中的 `k` 个 token 上进行。

复杂度从标准注意力的 `O(L²)`（L 是序列长度）降到 `O(L·k)`，当 `L` 远大于 `k` 时，这个降幅非常可观。DeepSeek 官方报告显示长文本场景下推理速度提升 2-3 倍，API 定价直接下调超过 50%，同时基准测试成绩和上一代稠密版本基本持平——说明"变稀疏"这件事本身并没有明显牺牲模型质量，前提是从头训练时就让模型适应这种稀疏模式（而不是拿一个稠密模型硬套稀疏推理）。

值得一提的是 DSA 和 NSA 的区别：NSA 是**块级（block-wise）**稀疏，DSA 是更细粒度的**逐 token 级**稀疏，工程实现上也和 DeepSeek 自家的 MLA（下一节详解）深度耦合在一起。到 2026 年年中，DeepSeek 在研究预览的 V4 架构中进一步提出了 **CSA（压缩+DSA 组合）和 HCA（更极端的压缩）交替混合**的方案，目标是支撑百万级 token 上下文。

## 7. 另一条路：Multi-Head Latent Attention（MLA，2024）

前面 MQA/GQA 是"减少 K/V 的头数"，DSA 是"减少要关注的 token 数"，**MLA 走的是第三条路：把每个 token 的 K/V 压缩到一个更低维的"潜在空间"里再缓存**，用的时候再投影回原始维度。这是 DeepSeek 在 V2（2024）中提出、V3/R1 延续使用的核心创新之一。

### 7.1 低秩联合压缩的直觉

标准做法是给每个注意力头都存一份完整维度的 K、V。MLA 的想法是：与其存 N 份完整的 K/V，不如先把输入压缩成一个**共享的、维度小得多**的"潜在向量"（latent vector），所有头都从这同一个潜在向量里，通过一个轻量的上投影矩阵反推出各自需要的 K/V。

```
c_t^KV = h_t · W^DKV                          # 下投影：压缩成低维潜在向量（这是真正被缓存的东西）
K^h = c_t^KV · W^UK_h,   V^h = c_t^KV · W^UV_h # 上投影：需要时再还原出每个头的 K/V
```

用 DeepSeek-V3 的实际数字直观感受一下压缩幅度：标准 MHA 每个 token 需要缓存 128 个头 × 128 维 = 16384 个浮点数；MLA 每个 token 只需要缓存大约 576 个数（512 维压缩 KV + 64 维解耦 RoPE），差不多是 **28 倍**的压缩率。

### 7.2 Decoupled RoPE（解耦旋转位置编码）

这里有个技术难点：RoPE 要求对 Q、K 做"旋转"操作来编码相对位置，但旋转操作和"先压缩再投影回去"这套流程在数学上不完全兼容（旋转矩阵不能简单地被吸收进压缩投影里）。MLA 的解法是把每个头的 Q、K 拆成两部分：一部分走正常的低秩压缩路径（不加 RoPE），另一部分是一个**共享的、维度很小的"位置感知"分支**，专门加 RoPE、用于携带位置信息，两部分拼接后再算注意力分数。这就是"解耦"的含义。

### 7.3 Weight Absorption：推理时的巧妙变形

如果每次推理都老老实实按"压缩 → 还原成每个头的 K/V → 做标准注意力"这个顺序算，MLA 反而比标准注意力多算了几倍的矩阵乘法（用来换取显存带宽的节省）。工程上有一个"权重吸收"（weight absorption）技巧：利用矩阵乘法的结合律，把"上投影"矩阵直接吸收进 Query 或者最终输出的投影矩阵里，让解码阶段的计算路径退化成一个和标准 `scaled_dot_product_attention` 几乎一样的形式——这意味着 MLA 在解码阶段甚至不需要专门写自定义 GPU 算子，直接复用现成、高度优化的标准注意力内核就能跑。

### 7.4 MLA vs GQA：不只是省显存

DeepSeek-V2 论文里一个有意思的消融实验结论是：**GQA 在同等 KV Cache 大小下效果通常不如标准 MHA**（毕竟是被迫共享 K/V 的折中方案），而 MLA 经过仔细调优后，KV Cache 大小做到和 GQA 差不多、甚至更小的同时，效果反而能**持平甚至略微超过标准 MHA**。这也是 DeepSeek 选择 MLA 而不是更简单的 GQA 的关键原因——它不只是一个效率妥协，而是一次真正意义上的架构改进。

到了 2026 年年中，MLA 已经不只是 DeepSeek 自家的专利：Kimi K2 系列延续并放大了这套配方，GLM-5 系列把 MLA 和 DSA 叠加使用，Ling 2.5 把 MLA 和线性注意力做混合，甚至连做多语言模型的 Sarvam 团队也在自家两款不同大小的模型上分别验证了 GQA 和 MLA、并主动选择了 MLA 作为大模型的方案。

## 8. 线性注意力与混合架构的回归（2024-2026）

前面所有方案，不管怎么优化，本质上还是"softmax 注意力"这个大家族——要么减少存的量（MQA/GQA/MLA），要么减少算的量（DSA/NSA），复杂度的"数量级"多少还是和序列长度相关。还有一条更彻底的路：**把注意力从"和历史所有 token 比对"，改造成一个类似 RNN 的、固定大小状态的循环结构**，这样无论序列多长，每一步的计算量和显存占用都是**常数**。这就是线性注意力（Linear Attention）和状态空间模型（SSM，如 Mamba）想解决的问题。

### 8.1 早期线性注意力为什么没有大规模成功

2020 年前后的 Performer、Linear Transformer、Linformer 等工作，本质上是用核函数近似或者低秩近似替代 softmax，把 `O(n²)` 的注意力算成 `O(n)`。但这些早期方案有个共同短板：**"记忆"能力弱**，尤其在需要精确检索久远上下文中某个具体细节的任务（比如"文档第 3 页提到的那个数字是多少"）上，表现明显不如标准注意力——因为它们把所有历史信息都压进了一个大小固定的状态里，天然存在信息瓶颈，这也是它们当年没能取代 Transformer 主流地位的核心原因。

### 8.2 状态空间模型与 Gated DeltaNet

2023-2024 年,以 Mamba 为代表的状态空间模型（SSM）重新证明了线性复杂度序列建模是可行的，配合"选择性"机制（让模型自己决定该记住什么、忘记什么），在不少任务上能追上 Transformer。后续 **Gated DeltaNet**（把 Mamba-2 的门控机制和 DeltaNet 的"增量更新规则"结合）成为 2025-2026 年一系列开源大模型采用的线性注意力主力方案，核心直觉是：

```
每一步用一对可学习的门（alpha 控制"忘掉多少旧记忆"，beta 控制"新信息写入多强"）
更新一个固定大小的"快速权重"状态，这个状态就是模型对全部历史的压缩总结
```

状态大小不随序列长度增长——这是它相比 KV Cache（会随序列线性增长）最大的吸引力所在。

### 8.3 混合架构：既要效率，也要精确检索

单纯用线性注意力替换全部层，长程精确检索能力还是会打折扣。2025-2026 年的实践共识变成了**"混合"**：绝大多数层用便宜的线性注意力处理局部/摘要式信息，每隔几层保留一层标准（或压缩过的）softmax 注意力，专门负责需要精确检索的场景。典型代表：

- **Qwen3-Next / Qwen3.5**：以 3:1 的比例交替堆叠"Gated DeltaNet 块"和"Gated Attention 块"（每 3 层线性注意力后接 1 层标准注意力），原生支持 262k、可扩展到约 1M 的上下文。
- **Kimi Linear / Kimi K3**：用 **Kimi Delta Attention（KDA）**——Gated DeltaNet 的进一步精细化版本，把 Qwen3-Next 里"每个头一个标量遗忘门"升级成"每个特征通道单独一个遗忘门"，记忆控制更精细；配合门控 MLA 层，同样是接近 3:1 的比例。到 2026 年年中的 Kimi K3（总参数约 2.8T，激活约 104B，支持 1M 上下文）里，93 层中有 69 层是 KDA、24 层是门控 MLA，官方声称在 1M 长上下文下 KV Cache 可减少约 75%、解码速度提升数倍。
- **Jamba / Nemotron 系列**：更早期的代表，把 Mamba 模块和标准自注意力模块直接交替堆叠。

### 8.4 一个重要的反例：MiniMax 的"回退"

线性/混合注意力的故事并不是"一路凯歌"。MiniMax 团队早期的 MiniMax-01/M1 用了线性+softmax混合注意力，但在后续 230B 参数的 **M2** 模型上，团队却选择了**回退到纯粹的标准 GQA**，不再使用线性注意力。他们给出的原因是：线性注意力在常规问答场景下表现尚可，但在**推理密集型任务**和**多轮、长程依赖的智能体（agentic）任务**中，精度会明显下降——而这恰恰是 2026 年最受重视的两类能力。这提醒我们：**线性/混合注意力目前还不是"免费的午餐"，是否采用、如何配比，在业界仍然是一个活跃的、没有定论的工程权衡**，不同团队基于自己的目标场景给出了不同答案。

## 9. 2026 年年中全景图：主流模型都在用什么

截至 2026 年 8 月，可以看到几条清晰但并未收敛成"单一答案"的技术路线，下表汇总了几个代表性模型的选择：

| 模型 | 核心注意力方案 | 主要特点 |
|---|---|---|
| DeepSeek V3.2 / V3.2-Speciale | MLA + DSA | Lightning indexer 打分 + top-k（默认2048）选择，复杂度 O(L·k) |
| DeepSeek V4（研究预览） | CSA（压缩+DSA）与 HCA 交替混合 | 面向百万级 token 上下文的更激进压缩 |
| GLM-5 / GLM-5.2 | MLA + DSA（5.2 新增 IndexShare） | 相邻层之间复用已选中的稀疏位置，进一步降低索引开销 |
| Qwen3-Next / Qwen3.5 | Gated DeltaNet : Gated Attention ≈ 3 : 1 | 原生 262k，可扩展至约 1M 上下文 |
| Kimi Linear / Kimi K3 | Kimi Delta Attention : 门控 MLA ≈ 3 : 1 | 逐通道门控，1M 上下文下 KV Cache 降幅显著 |
| MiniMax M2 / M2.5 | 纯 Grouped-Query Attention | 主动放弃线性注意力，换取推理密集/智能体任务的精度稳定性 |
| Ling 2.5 | MLA + 线性注意力混合 | 与 Kimi/Qwen 路线并行的另一种混合配方 |

几个值得记住的观察：

- **没有"终局答案"**：2026 年年中同时并存至少三条主流路线——「MLA+DSA稀疏」「线性/softmax混合」「保守GQA」——不同团队根据自己最看重的场景（超长上下文成本、agentic 任务稳定性、工程实现复杂度）做出了不同取舍。
- **"省 KV Cache"和"省计算量"是两个可以叠加的正交问题**：MQA/GQA/MLA 解决前者，DSA/NSA/线性注意力解决后者（严格说线性注意力两者都省），FlashAttention 系列解决"同样的计算怎么让硬件跑得更快"，三条线互不冲突，实践中经常同时出现在同一个模型里（比如 DSA 就是构建在 MLA 之上的）。
- **推理框架是新瓶颈**：像 vLLM、SGLang 这样的开源推理引擎需要为每一种新注意力变体（MLA 的权重吸收、DSA 的稀疏索引 kernel、Gated DeltaNet 的循环状态管理）单独适配高性能算子，一个新架构从论文发布到能在生产环境里跑满硬件算力，中间往往有几个月的工程滞后——这也是为什么"算法论文"和"能用的产品"之间总会有时间差。

## 10. 总结：一张表看懂所有权衡

| 技术 | 提出时间 | 解决的问题 | 代价/权衡 |
|---|---|---|---|
| Bahdanau/Luong Attention | 2014-2015 | Seq2Seq 定长瓶颈 | 依然基于 RNN，无法并行 |
| Scaled Dot-Product + Multi-Head（Transformer） | 2017 | 摆脱 RNN，可大规模并行训练 | 计算/显存随序列长度平方增长 |
| MQA | 2019 | KV Cache 显存过大 | 所有头共享K/V，精度有损失 |
| GQA | 2023 | MQA 精度损失过大 | 折中方案，需要调组数超参 |
| FlashAttention 系列 | 2022-2026 | 显存读写（IO）是速度瓶颈 | 不减少KV Cache，只加速计算/降低显存峰值 |
| NSA / DSA | 2025 | O(n²) 计算量在长上下文下不可承受 | 需要从预训练阶段就适配稀疏模式，工程实现复杂 |
| MLA | 2024 | 在不牺牲（甚至提升）效果的前提下压缩 KV Cache | 解码路径需要"权重吸收"等专门工程技巧才能高效 |
| 线性注意力 / Gated DeltaNet / KDA | 2024-2026 | 让计算和显存彻底摆脱序列长度的影响 | 长程精确检索能力天然弱于softmax注意力，需要混合稀疏/软注意力兜底 |

如果只记住一句话：**注意力机制的演进史，就是一部不断在"表达能力"和"计算/显存成本"之间寻找新平衡点的历史**——而 2026 年的现状告诉我们，这个平衡点仍然因场景而异，远没有到"一个方案通吃"的阶段。
