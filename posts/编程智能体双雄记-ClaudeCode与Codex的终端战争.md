我用这两个工具快一年了，和大多数人一样经历了完整的心理曲线：先是"Claude Code 真香"，然后是"Codex 怎么这么省 token"，最后是两个都留着、按任务类型换着用。但每次有人问我"到底该用哪个"，我都得现场重新组织一遍答案——这个问题的答案每个月都在变。把两头的发展史从头捋了一遍之后，结论其实很清爽：**这又是一次 vLLM vs SGLang 式的双雄格局——哲学相反、能力趋同、长期共存，而且"两个都用"是理性解**。但"哪个任务用哪个"的分界线，值得专门写一篇来讲清楚。

还有一个背景让这场战争值得记录：上一篇刚讲过 SWE-bench Verified 之死和基准测试的信任危机，而这场战争的双方恰恰是那张死去榜单上的前两名——Claude Code 背后的 Opus 系列长期霸榜，Codex 背后的 GPT-5.x-Codex 紧咬不放。**模型层的战争在评测榜上打，智能体层的战争在开发者的终端里打**，后者才是 2026 年真正决定市场份额的战场。

## 1. 引子：一场被 ChatGPT 抢先命名的战争

先交代一个容易搞混的事实：**这篇文章写的"Codex"和 2021 年那个叫 Codex 的模型不是同一个东西，但确实有关系**。名字是复用的，血统是断的——这段历史本身就是个精彩的行业故事，第 2 节专门讲。

把舞台先搭一下。2025 年初，"AI 编程工具"的主流形态还是 IDE 里的补全和侧边栏聊天：GitHub Copilot 有 180 万订阅用户，Cursor 刚靠 Agent 模式起势。终端里基本是空地——那个位置曾经属于更老的抽象（shell、make、别名脚本），从来没人觉得"在终端里跑一个自主改代码的 AI"是个产品。

然后 2025 年 2 月 24 日，Anthropic 随 Claude 3.7 Sonnet 发布了 Claude Code 的研究预览版；7 周之后的 4 月 16 日，OpenAI 开源了 Codex CLI。**一个新品类在七周内有了两个重量级玩家**，而且各自背后是当时最强的两家模型公司。此后十八个月的演化速度，用任何历史类比都显得保守：终端 agent 从"能读能写的聊天"长成了"多智能体编排平台"，市场在三十个月里向三个产品集中了 70% 以上的份额，而开发者每周花在审查 AI 代码上的时间（11.4 小时）第一次超过了写新代码的时间（9.8 小时）。

这篇文章要回答的问题只有一个：**这两个长得越来越像的工具，骨子里到底差在哪，以及这个差异对你意味着什么**。

## 2. 前传：Codex 这个名字的两次生命（2021-2023）

要讲清 Codex，得先讲它的前世，因为这段历史决定了它的两次命名逻辑完全不同。

2021 年 7 月，OpenAI 发表论文，把 GPT-3 在 54M 个 GitHub 仓库的 159 GB Python 代码上继续训练，得到了 **Codex**——第一个证明"通用语言模型微调一下就能写代码"的模型，HumanEval 上 28.8% 的 pass@1（第六篇讲过，HumanEval 就是随这篇论文一起发布的）。它随后成为第一代 GitHub Copilot 的引擎，2021 年 8 月上了 API，2022 年的 code-davinci-002 甚至成了 GPT-3.5 的前身——**可以说没有 Codex 就没有 ChatGPT**。但 2023 年 3 月 23 日，OpenAI 把 Codex API 正式弃用，这个名字沉寂了两年。

转折发生在 2024 年底到 2025 年初。Anthropic 沿着"模型 + 工具 + 终端"的路线悄悄做 agent，2024 年 10 月发布 Claude 3.5 Sonnet (new) 和计算机使用能力时，已经显露出"让模型操作真实环境"的野心。据后来广泛流传的说法，2025 年 Claude Code 预览版出来并快速起量之后，OpenAI 内部拉响了"Code Red"（红色警报）——这个名字后来也被用来形容他们在搜索、浏览器等多条战线上对竞品的紧急响应。

于是有了那个颇具戏剧性的决策：**把"Codex"这个带有正统血统的名字，从坟墓里挖出来，安在新的终端 agent 身上**。2025 年 4 月 16 日，Codex CLI 作为开源工具发布（Apache 2.0），同期上线的还有 o3 和 o4-mini。五周后的 5 月 16 日，云端版 Codex（研究预览）跟进，跑在为软件工程微调的 codex-1 上。

这里有个值得停留一下的细节：Claude Code 的发布是"模型驱动的"——3.7 Sonnet 的混合推理能力让终端 agent 第一次够用，工具是模型的展示橱窗；而 Codex CLI 的发布是"竞争驱动的"——它是 OpenAI 对 Anthropic 市场动作的快速反应，TypeScript 写的、UI 用 React Ink 拼的，明显是抢时间的产物。**一个是"我能做到了所以做"，一个是"对手做了所以我必须做"**——这个出身差异贯穿了两者后来的整个演化节奏：Claude Code 按模型代际稳步迭代，Codex 则展现出更激进的重构勇气（后面会讲到它一年内把自己从 TypeScript 重写成 Rust）。

## 3. Claude Code 简史：从终端实验到十亿美元产品

### 3.1 出身（2025 年 2 月-5 月）：一条被验证的路线

Claude Code 发布时朴素得像个学术 demo：装在终端里，能读文件、写文件、跑命令，Agent Loop 就是"读-想-改-跑"的循环，没有任何现在习以为常的东西——没有 plan mode，没有 CLAUDE.md，没有 hooks，上下文 200K。早期用户得在提示词里手动描述项目结构，因为模型自己不会探索。

但三个设计判断从第一天就没变过，回头看这是它后来所有演化的种子：

1. **终端优先**。不上 IDE 插件、不做网页，先做终端——因为终端是开发者唯一全平台统一的"操作系统级"入口，做进去就天然支持所有语言和工具链；
2. **本地执行**。直接跑在用户机器上、直接访问真实文件系统——牺牲了隔离性换来了零摩擦和完全透明；
3. **协作而非委派**。默认工作模式是"你在旁边看着它干活"，敏感操作会停下来问。这三个判断合起来定义了一种"副驾驶"哲学，和后来 Codex 的" autopilot"哲学形成全面对照。

2025 年 5 月 22 日，随 Claude 4（Opus 4/Sonnet 4）一起 GA。Opus 4 那时在 SWE-bench 上拿 72.5%，能连续自主工作数小时——**GA 之日的 Claude Code 已经是当时最强的终端 agent，但真正的爆发在后面**。

### 3.2 平台化（2025 年 9 月-2026 年 2 月）：功能大爆炸

2025 年 9 月 29 日是个节点性的日子。随 Sonnet 4.5 一起，Claude Code 迎来一波至今看来都算密集的功能投放：**checkpoints**（任意回滚到之前状态）、**subagents**（子代理在独立上下文里干活）、**hooks**（在工具调用生命周期上挂钩子）、原生 VS Code 扩展，以及把内部基础设施开放成的 **Claude Agent SDK**。同一时期 Anthropic 还发了句后来被反复引用的话：Sonnet 4.5 能在复杂任务上保持专注超过 30 小时。

2025 年 10 月 20 日，**Claude Code on the web** 上线——云沙箱里跑、连 GitHub 仓库、并行多任务、自动开 PR，随后 iOS 也能用。注意这个时间点：**Claude Code 用了八个月把自己从"终端工具"扩展成"全形态产品"**（终端、IDE、桌面、网页、移动端），这个速度后来成了它对 Codex 的主要优势之一。

2025 年 11 月 Opus 4.5、2026 年 2 月 5 日 Opus 4.6（带来 1M token 上下文 beta）、Background Agent 转 GA。到这时候，"派一个任务然后关电脑走人"已经是官方工作流了。

### 3.3 编排时代（2026 年 4 月-8 月）：从工具到平台

2026 年是编排之年。4 月：**Routines**（定时任务）、Opus 4.7 成为默认模型、Ultraplan/Ultrareview（云端规划和审查智能体舰队）。5 月：**Dynamic Workflows**（用 JavaScript 脚本编排成百上千个并行子代理）、Opus 4.8 默认。6 月：子代理可以递归再派子代理（五层深度）。8 月：跨会话 agent、自托管 runner。

有组数字能说明这十八个月的烈度：Claude Code 从发布到十亿美元年化收入用了六个月；到 2026 年年中，**它贡献了公开 GitHub 全部 commit 的约 4%**（5 月峰值单日 40 万次）；Anthropic 整体 25 亿美元 ARR（2026 年 2 月）里它是第一驱动力。连微软内部都在用——尽管自家有 Copilot。

### 3.4 一个反直觉的架构事实

2026 年有篇论文分析了 Claude Code v2.1.88 的源码快照（约 1,884 个 TypeScript 文件、51.2 万行），结论被广泛引用：**核心 AI 决策逻辑只占代码量的约 1.6%，剩下 98.4% 是"运营性 harness"**——权限系统、上下文管理、工具路由、错误恢复、会话持久化。核心 agent loop 本身就是一个朴素的 while 循环。

这个数字值得所有做 agent 的人记一下。它印证了 Anthropic 的设计哲学：**不要试图把聪明写进流程图，让模型自由判断，但把它放进一个确定性、可审计、安全的运行环境里**——所谓"最小脚手架、最大运营 harness"。模型负责"想做什么"，harness 掌握"能不能做"。第五篇讲 vLLM V1 重构时说过推理引擎的竞争力在调度不在 kernel，这里是同一个道理的 agent 版：**agent 产品的竞争力在 harness，不在 loop**。

## 4. Codex 简史：从紧急应战到三百万周活

### 4.1 出身（2025 年 4-6 月）：抢时间的开源先锋

Codex CLI 的首发版很"轻"：TypeScript + React Ink，npm 一装就能跑，随 o3/o4-mini 一起亮相。但它带着两个 Claude Code 当时没有的属性：

**第一是开源**。Apache 2.0，代码全公开。在 Cursor、Copilot 全是闭源的市场里，这是刻意的差异化——OpenAI 押注透明能换来开发者信任，后来证明押对了：仓库几周内收获上万 star，社区分支给它接上了 Gemini、Ollama、OpenRouter 等第三方后端，生态自发生长。

**第二是沙箱优先**。从第一版起，Codex 就把"命令跑在隔离环境里"当作默认而非选项——这个基因后来长成了它和 Claude Code 最大的架构分野（下一节细讲）。

2025 年 5 月 16 日云端版上线，跑 codex-1（o3 在软件工程任务上的微调版），每个任务一个隔离容器，可以并行多个。2025 年 6 月接入 ChatGPT 主产品（网页版），从此**买 ChatGPT 订阅就送 Codex 额度**——这个分发决策后来被证明极其关键。

### 4.2 模型线独立成军（2025 年 9 月-2026 年 2 月）

2025 年 9 月 15 日，**GPT-5-Codex** 发布——GPT-5 的编码特化版，Codex 从"套壳调用通用模型"升级为"有专属模型线的产品"。这条线随后以惊人的节奏迭代：GPT-5.2-Codex、然后是 2026 年 2 月的戏剧性一幕——**Anthropic 发布 Opus 4.6 半小时后，OpenAI 紧急推出 GPT-5.3-Codex**，被硅谷舆论称为"一夜两弹"。GPT-5.3-Codex 融合了当时顶尖的编程与推理能力，速度提升 25%，OpenAI 甚至说它是"第一个在自身创造过程中发挥关键作用的模型"——用 Codex 开发 Codex。

同期（2026 年 3 月），OpenAI 做了一个更大的战略动作：把 **ChatGPT、Codex、自研浏览器 Atlas 整合成统一桌面超级应用**。从 Sam Altman 之前提倡的"一百个小赌注"转向"一个大押注"——触发因素就是 Claude Code 在开发者市场的快速渗透。Codex 从一个防御性产品变成了 OpenAI 生态的三大支柱之一。

### 4.3 规模化（2026 年 3-8 月）：效率怪兽

2026 年 3 月 14 日，多智能体子代理 GA（最多 8 个并行）。4 月，Codex CLI 周活用户突破 **300 万**。5 月，Goal mode（让 Codex 为一个目标连续驱动数小时甚至数天）、Appshots（把任意应用窗口截图发给 Codex 当上下文）、锁定状态下远程计算机使用、Hooks 正式发布。7 月，用户数冲到 **800 万**量级。

还有一件工程大事值得一提：**从 TypeScript 到 Rust 的完全重写**。一年内把整个 CLI 推倒重写、代码库 96.5% 是 Rust，这个决定换来了启动速度和资源占用上的代差优势（428+ 贡献者、879 个 release 的节奏也侧面说明了社区热度）。加上和 GitHub 的深度集成（Issue 里 @Codex 自动认领、自动代码审查），到 2026 年年中，**Codex 在"每周要用、但 Claude Code 优先"的次席位置上长成了庞然大物**——市场份额大约 11%，但增长速度全场最快。

### 4.4 Token 效率：被反复验证的代差

如果说 Claude Code 的杀手锏是"一次做对率"，Codex 的杀手锏就是**token 经济学**。社区反复复现的一组对比：同一个 Figma 插件任务，Codex 用了 150 万 token，Claude Code 用了 620 万——4 倍差距；一个调度器应用，7.3 万对 23.5 万——3.2 倍。原因不难猜：GPT-5.x-Codex 是专门为 agentic 编码微调的模型，工具调用路径更"短直"，而且 Codex 的 harness 在上下文管理上更激进（自动压缩、按需加载）。

**同样跑一天活，Codex 的 API 账单经常只有 Claude Code 的三分之一**——在按 token 计费的世界里，这不是小数点问题，是预算问题。

## 5. 架构对撞：本地协作 vs 云端委派

把两头的历史摆完，现在可以正面回答那个核心问题了：**这两个工具骨子里差在哪**。答案不在模型（模型各有胜负），在 harness 哲学。用一个对照表先收拢事实，再展开讲四条最深的分野。

| 维度 | Claude Code | Codex |
|------|------------|-------|
| 执行位置 | 本地优先（用户机器直接跑） | 云沙箱优先（隔离容器） |
| 默认工作模式 | 协作（看得见每步，敏感操作询问） | 委派（"收到，我去处理"） |
| 项目说明文件 | CLAUDE.md（分层，最多 ~200 行建议） | AGENTS.md（嵌套覆盖，默认嵌入 32 KiB） |
| 补丁格式 | str_replace（外科手术式精准替换） | apply_patch（统一 diff） |
| 沙箱 | 主机 shell + 可选隔离 | Docker 级隔离默认开启 |
| 扩展机制 | MCP（生态最成熟）+ hooks + skills | custom_tools JSON schema + config.toml |
| 多智能体 | Agent Teams、子代理递归五层、Dynamic Workflows | 最多 8 个并行子代理 |
| 开源 | 否 | 是（Apache 2.0，Rust） |
| 上下文 | 200K 默认 / 1M（Opus） | 400K 默认（实测可用约 258K） |
| 推理控制 | 软性（提示词引导） | 显式档位（minimal/medium/high/xhigh） |

### 5.1 信任模型：透明 vs 隔离

这是所有分野的根。Claude Code 赌的是**"让开发者看见一切"**：每一步实时输出到终端，改文件前问一句，出了问题你全程目睹，心里有底。Codex 赌的是**"让环境兜住一切"**：任务扔进隔离容器，模型在里面怎么折腾都碰不到你的机器，干完回来交 diff。

两种信任各有软肋。透明模式的软肋是**摩擦**——每一步都确认，长任务能把人钉在终端前；隔离模式的软肋是**黑盒**——中间过程看不见，出问题只能看结果猜原因（虽然 Codex 后来加了完整的执行日志回放来补这块）。2026 年的实际演化是两边都在往中间走：Claude Code 加了沙箱模式和 auto-accept 档位，Codex 加了实时过程流和 Hooks——**但出身决定气质，用起来手感至今截然不同**。

### 5.2 上下文策略：大窗口 vs 会掐着用

Claude Code 的路线是"把窗口做大"：Opus 系列的 1M 上下文在 2026 年 3 月后成为 Max/Team 档默认，整个中等仓库可以直接塞进去。Codex 的路线是"把窗口用精"：默认 400K（实测可用约 258K），自动压缩随时待命，`model_auto_compact_token_limit` 可以调触发阈值。

哪条路线更好取决于任务形态。**大探索、多文件重构、需要全局视野的活**，大窗口是碾压性优势——Claude Code 处理"改 12 个文件、依赖关系复杂"的任务时那种"胸中有丘壑"的感觉，很大程度是 1M 上下文给的。**长会话、高吞吐、批量重复的活**，精细管理更划算——Codex 的压缩策略和 3 倍 token 效率，让它在"同样预算多干三倍的活"这个维度上无人能敌。

值得一提的还有两个细节：Claude Code 的 `/context` 命令能精确显示 token 都花在哪了（排查上下文问题的第一利器）；而 Codex 超过 272K 输入阈值后会进更高计费档，官方 issue 区不少人踩过这个坑。

### 5.3 指令文件：两种"项目记忆"观

CLAUDE.md 和 AGENTS.md 是两个工具最像的地方——都是"给 agent 看的 README"，都支持分层覆盖（子目录优先于根目录）。但社区沉淀出的写法心法已经分岔了：

**CLAUDE.md 的生态观是"规则体系"**：官方建议单文件不超 200 行，长内容拆进 `.claude/rules/` 目录（可按文件路径生效），配合 settings.json 三级作用域（用户级/项目级/团队级）做权限分层。写法上强调"写指令不写文档"——写"改完必须跑 pnpm test"，不写"我们的测试很重要"。

**AGENTS.md 的生态观是"操作手册"**：社区共识是 100 行为佳、硬上限 300 行，只写"模型自己猜不到的信息"（用 pnpm 不用 npm、这个目录不能手改、提交前必须跑哪三条命令），因为**它能从代码推断出来的东西写进去全是浪费上下文**。Codex 的显式推理档位（minimal 到 xhigh）配合这套手册，把"什么时候该多想"变成了可调参数——这是 Claude Code 需要用提示词绕着实现的东西。

### 5.4 扩展生态：开放标准 vs 自家后院

MCP（Model Context Protocol）是 Anthropic 主推的开放标准，Claude Code 是它的第一等公民——数据库、工单系统、浏览器、内部 API，`mcp add` 一条命令接上，社区服务器数量 2026 年已经过千。再加上 hooks（生命周期任意位置挂钩子）和 skills（可安装的方法论包，SKILL.md 生态已过 2800 个），Claude Code 把自己做成了**平台**：平台团队可以用 managed policy 锁权限、审计每一步，这也是它在企业市场（尤其金融、医疗这些"不能出事"的行业）占优的底层原因。

Codex 的生态思路更"紧"：custom_tools 的 JSON schema 扩展、config.toml 集中配置、插件系统 2026 年 5 月才向 Business 开放共享。但它的王牌是**开源本身**——社区分支不受任何厂商限制地接入了所有主流模型后端，这个"逃逸自由"是闭源的 Claude Code 永远给不了的。

## 6. 基准与真实：分数之外的分野

第六篇刚讲过基准测试的信任危机，所以这节先打预防针：**下述所有分数都请带着那篇的教训读**。两边各有一张"自家战场"的优势榜——Claude Code 在 SWE-bench Verified 上拿过 87.6%（Opus 4.8 驱动，那也是这张死掉榜单的最后传奇之一），Codex 在 Terminal-Bench 2.0 上拿 77.3%、2.1 上 83.1%（对 Claude Code 的 83.8%）——**各自主场，各自领先，而且差距都在模型换代的一夜之间翻过面**。真正稳定、跨代际成立的是下面这些"分数之外"的分野：

**一次做对率**。多文件复杂改动，Claude Code 的首过正确率更高，意味着更少的"改-跑-炸-再改"循环。这个差距的来源大概率是 Opus 系列在长 horizon 任务上的训练倾向（Anthropic 官方口径：Opus 4.8 保持专注超 30 小时），以及 1M 上下文给的"全局感"。

**速度与成本**。Codex 标准档 65-70 token/秒（Spark 变体在 Cerebras 硬件上宣称 1000+），配合 2-4 倍的 token 效率，**同样的活 Codex 经常又快又便宜**。Claude Code 快感上吃亏，但换来的是少返工——一次做对的"慢"比三次返工的"快"便宜。

**并行形态**。Claude Code 的并行是"舰队"式的：Agent Teams、Dynamic Workflows、五层子代理递归，适合"一个复杂任务拆给一个团队"；Codex 的并行是"车间"式的：最多 8 个子代理、云端多任务并行、Goal mode 单任务长跑，适合"一批独立任务分给八个工位"。前者像项目组，后者像流水线。

**市场份额的走向**比任何单次基准都诚实：2026 年年中各家口径里 Claude Code 稳居第一（14-28%，看统计方法），NPS +58 全场最高；Cursor 第二；Copilot 缓降；Codex 11% 但增速最快。而**70% 的开发者日常同时用 2-4 个工具**——这个数字本身就是本文结论的预演。

## 7. 使用心法：两个工具各自的正确打开方式

这节是给真用的人写的。两边各挑最值钱的几条，都是社区反复验证过、2026 年 9 月当前版本可用的。

### 7.1 Claude Code 心法

**心法一：Plan Mode 是第一生产力**。复杂任务永远走"探索 → 计划 → 执行"三段：Shift+Tab 切到 plan mode，让它读完代码库先出实施计划，你审完再放行实施。社区甚至进化出了"Claude Code 规划、Codex 审查"的混合流（毕竟让另一家的模型看自家计划，没有立场偏袒）。**跳过计划直接让它干，是新手浪费 token 的第一大原因**。

**心法二：CLAUDE.md 要"养"不要"写"**。`/init` 生成的初稿只是起点，真正值钱的版本是用出来的：每次纠正它的同一个错误，就把这条规矩写进去；会话里 `#` 开头能随手记一条进记忆。单文件控制在 200 行内，超了就拆 `.claude/rules/`。

**心法三：上下文是配给资源**。`/clear` 换任务就清，`/compact` 带指令压缩（"保留 API 设计相关的讨论"比裸压缩保真得多），`/context` 随时查余额。子代理不只是并行工具——**它是上下文防火墙**：探索性搜索、长日志分析这种"读完就没用"的中间产物，扔给子代理消化，只让结论回主线程，主上下文能多活一倍时间。

**心法四：hooks 干掉机械劳动**。PostToolUse 挂个自动格式化，改完就 format 不用你催；PreToolUse 拦危险命令，`rm -rf` 类操作直接打回。配置一次，永久生效——这是把"每次提醒"变成"从不需要提醒"的杠杆。

**心法五：`claude -p` 无头模式**。把 Claude Code 当 Unix 命令用，塞进 shell 脚本和 CI 里，`claude -p "检查这个 diff 有没有安全问题" && ...`——终端工具的最后形态是消失在管道里。

### 7.2 Codex 心法

**心法一：AGENTS.md 只写"猜不到的"**。包管理器用什么、哪些目录禁改、提交前必须跑什么——写这些。凡是能从代码推断的（"这是 React 项目"）一行都别写，纯烧上下文。规则多就往子目录拆，嵌套越深优先级越高。

**心法二：让推理档位跟着任务走**。改个错别字用 minimal，debug 疑难杂症上 xhigh。显式档位是 Codex 最被低估的参数——**Claude Code 用户需要用提示词实现的"想多点/想少点"，这里是个旋钮**。

**心法三：贴报错，只说 fix**。社区验证的成功率超 80% 的用法：完整贴上报错栈，一个字"fix"，不要引导。它自己的排查路径往往比你的猜测短——**指导得越少，修得越好**，这个反直觉经验专门为过度的"热心指导"准备。

**心法四：同一问题修不好两次就开新会话**。上下文污染是复修失败的头号原因，第三次尝试前重启会话、让 AGENTS.md 带着必要上下文重来，比在烂泥里继续挣扎快得多。

**心法五：委派任务用云端，看着任务用本地**。云端沙箱+8 并行适合"五个独立 feature 一起做"的批处理；本地 CLI 适合你在屏幕前盯着的交互会话。**Codex 的双形态不是冗余，是两种工作模式**。

### 7.3 通用心法（两家都吃）

- **给上下文，别给指令**。"我要改 X 因为 Y"比"你先这样再那样"效果好——agent 的路径规划比你准；
- **成果不满意就说"重做"而不是"修补"**。将就着打补丁，是平庸方案的温床；
- **敏感操作永远手动**。git push、数据库迁移、删文件——不管哪家工具，这两个字段的权限都该保持"每次询问"。

## 8. 未来展望：2027 年的终端会是什么样

往前看 12-18 个月，几条趋势的置信度高低不同，分开讲。

**高置信：战争在"编排层"继续，不在"模型层"**。两家 2026 年的重心都明确从模型转向了平台——Anthropic 5 月的开发者大会干脆跳过了新模型发布，全部篇幅给了 agent 编排功能（这个决策在模型军备竞赛正酣的当下相当激进）；OpenAI 把 Codex 塞进了 ChatGPT+Atlas 超级应用。**单打独斗的"最强单 agent"正在贬值，能调度舰队、能跨会话存活、能被企业治理的"平台"在升值**。

**高置信：多智能体协作从演示变日常**。五层递归子代理、Dynamic Workflows、八并行车间——这些 2026 年还带着实验标签的东西，2027 年会成为默认形态。配套地，**eval 会成为基础设施**：每次提示词变更跑回归、每次模型升级带 eval 增量，像今天的单元测试一样不可或缺——现在 90% 的团队还没有，这是最大的空白也是最大的机会。

**中置信：skills 生态成为护城河**。团队的隐性知识（怎么写前端、怎么做 code review、怎么排这类 bug）正在变成可安装、可继承的 SKILL.md 工件。招聘会开始为"技能编写能力"定价——新员工上手从"几个月"压缩到"几天"的杠杆，没人会拒绝。**谁的标准更开放、长尾更长，谁赢**——目前 Claude 系领先，但 Codex 的开源策略随时可能翻盘。

**中置信：市场集中度继续上升，但"双工具"成为常态**。70% 份额集中在三四个产品、开发者平均同时用 2-4 个工具的格局会固化。真正值得警惕的反而是依赖本身——切换成本随使用时间复利增长，而这正是评测失效的世界里，开发者唯一真实的"投票"方式。

**低置信但值得赌的**：审查取代编写成为核心技能。每周 11.4 小时审查对 9.8 小时编写的交叉已经发生，METR 的时间跨度还在以约 3 个月翻倍的速度增长。**"程序员"这个职业 2027 年的主职可能真的会变成"定义问题、验收结果"**——这个说法 2023 年像炒作，2026 年像天气预报。

## 9. 实战：2026 年 9 月怎么选

落到操作层面，按场景给结论：

| 你的情况 | 推荐 |
|---------|------|
| 复杂多文件重构、架构级改动 | Claude Code（一次做对率 + 1M 全局感） |
| 预算敏感、高吞吐批量任务 | Codex（token 效率 2-4 倍） |
| 企业采购、强合规要求（金融/医疗） | Claude Code（managed policy、权限体系、审计） |
| 想接自家内部工具/数据库 | Claude Code（MCP 生态） |
| 需要"扔下就走"的委派式工作流 | Codex（云沙箱 + Goal mode） |
| 想要开源可改造、多模型后端自由 | Codex（Apache 2.0） |
| 长会话长任务 | 各有千秋：Claude 靠大窗口，Codex 靠压缩管理 |
| 大多数活跃开发者 | **两个都开**（月成本 $40，认知成本约等于学会两个编辑器快捷键） |

以及几条超出二选一的实话：其一，**混合流正在成为高手标配**——Claude Code 做规划和复杂实施、Codex 做审查和批量杂活，社区里甚至有专门让 Codex 审查 Claude Code 产出的 hook 配置。其二，别忘了这个市场还有 Cursor（IDE 派，增长最快）和 Gemini CLI（免费额度最大方）——**"终端双雄"是本文的叙事框架，不是市场的全部**。其三，选型的影响比看起来大：选哪个工具就是选哪家的模型路线图，这个决定会随着你写进 AGENTS.md/CLAUDE.md 的每一行团队知识复利加深。

## 10. 尾声：七篇合奏

写完七篇，这个专栏恰好凑成了一条完整的链路：**注意力**和**分词**讲模型怎么理解世界，**量化**讲数字怎么在硬件上活下来，**AI Infra** 和**推理引擎**讲万卡集群和终端部署，**基准测试**讲我们怎么知道这一切在进步——而这篇讲的是这条链路的最后一环：**所有这些技术最终变成开发者手里那两个命令行工具的方式**。

写这七篇最一致的感想是：每一个层级都在发生同一件事——**"聪明"的性价比持续下跌，"工程"的占比持续上升**。Claude Code 那 1.6% 的决策代码对 98.4% 的 harness，vLLM 那 5ms 的 kernel 对一整套调度器，FrontierMath 那些被审计出 42% 错误的题——模型、引擎、评测、工具，全都在经历同一场从"演示"到"运营"的成人礼。终端里的这场战争没有输家：两个哲学相反的产品互相追赶，十八个月把 agent 从玩具推成了基础设施。而下一次你敲下 `claude` 或 `codex` 的时候，指尖底下就是这个专栏七篇文章的全部内容。
