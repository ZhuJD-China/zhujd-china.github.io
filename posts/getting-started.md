> 观水有术，必观其澜。—— 《孟子·尽心上》

技术的浪潮奔涌向前，与其随波逐流，不如静观其澜：观是输入，澜是思考，行是输出。这里是 **观澜阁** 的开篇指南，三分钟读完，即可开始写作。

## 三步发布一篇文章

### 第一步：新建文件

在 `posts/` 目录下新建一个 `.md` 文件（文件名建议用英文，它也是文章的网址）：

```
posts/my-new-post.md
```

### 第二步：写头部信息

```markdown
---
title: 文章标题
date: 2026-08-21
tags: [技术, 教程]
excerpt: 一句话摘要，显示在首页卡片上。
album: 深度学习专栏
order: 1
---

正文从这里开始……
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| title | 建议 | 文章标题 |
| date | 建议 | 发布日期，首页按它排序 |
| tags | 可选 | 标签数组，自动生成筛选器 |
| excerpt | 可选 | 摘要；不写则自动截取正文 |
| album | 可选 | 所属专辑名称，相同名称自动归为一辑 |
| order | 可选 | 在专辑中的序号，用于连载排序 |

### 第三步：推送

```bash
git add posts/my-new-post.md
git commit -m "发布新文章"
git push
```

推送后文章即刻上线，**无需修改任何其他文件**。

## 专辑：把连载装订成册

一个专辑就是一个系列合集 —— 多篇 `.md` 写上相同的 `album` 名称即自动成辑，配合 `order` 控制连载顺序：

- 首页「专辑」区自动生成专辑卡片，点击进入专辑目录页
- 文章页顶部显示所属专辑，底部提供**上一篇 / 下一篇**导航
- 适合教程连载、系列研究笔记等场景

> 单篇文章不写 `album` 字段即可，保持独立发布。

## 架构哲学：部件越少，系统越稳

本站基于 GitHub Pages 纯静态搭建，没有后端、没有数据库、没有构建流程：

1. **零配置的内容发现** —— 首页通过 GitHub Contents API 自动发现 `posts/` 下所有 `.md`，增删文件即增删文章
2. **客户端渲染** —— Markdown 由浏览器端 marked.js 实时渲染，搜索、标签过滤、专辑分组均为本地计算
3. **优雅降级** —— API 限流时使用本地缓存与 `posts/index.json` 兜底清单（由 GitHub Action 自动维护）

写作的最大敌人是流程摩擦。当发布一篇文章只需要「保存文件 + 推送」时，写作的心流才不会被工具打断。

> 最好的架构，是让你忘记架构的存在。现在，去写你的第一篇文章吧。
